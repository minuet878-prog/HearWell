# 給 Claude Code：下一階段「讓家屬找得到」

請先把這份文件存成 `docs/planning/found-by-family/plan.md`，並在 `docs/roadmap.md` 的「下一步」加一條指向它。
然後照 `CLAUDE.md` 的流程，從第 1 項開始。

## 怎麼做

- 六項各開一份母規格，照順序做；每一項都先拷問我、寫規格、拆票、先寫測試、審查、驗收。
- 「已決定」是拷問的起點，我可以推翻；「要問我」的項目請在拷問時問，不要自己決定。
- 第 2、3、4 項不依賴我寫的內容，可以連續做。第 5 項要等我交內文，沒交之前先做別的。
- 不用登入就能送資料進來的入口（回饋、取消提醒連結），一律要做交叉審查，不能略過。
- 會動到同意書的修改集中在第 4 項，整個階段只升一版。升版前先告訴我有哪些項目一起進去。
- 臨床內容、衛教文字、信件內文都由我寫。請不要自己生成，只準備版面和放文字的位置。
- 先暫停 roadmap 上的便當格、聽力護照、故事卡片、家人模式、情境日記、噪音計，這個階段做完再說。

## 背景

開放階段第 1–3 項已上線（免註冊先篩檢、Google 登入、LINE 登入），但還沒有人知道這個網站。
我的判斷：長輩和家屬都會用，但會上網找資料的主要是家屬，長輩那一側靠家屬把連結傳給他，或聽力師當面給。

家屬在門診最常問的五句話（原話）：
1. 我爸媽的聽力還好嗎？
2. 為什麼跟他講話都一直「蛤」？
3. 看電視都要開很大聲，受不了。
4. 有沒有推薦的助聽器？
5. 助聽器是不是都很貴？

第 1、3 句站上沒有對應頁面；第 2 句有「怎麼跟聽損的家人說話」和聽損模擬，但沒解釋原因；
第 4、5 句有內容，但標題是網站的分類（「助聽器｜聽伴」「補助檢核｜聽伴」「期限試算｜聽伴」），不是家屬的話。

## 第 2 項：搜尋基本功

已決定：
1. 只做自然搜尋，不買廣告。
2. 提供 sitemap，只列不用登入的公開頁面：首頁、了解、家人專區各頁、選配指引各章、問答小助手的主題與答案頁、聽損模擬、隱私權說明，以及這個階段新增的頁面。
3. 要登入的頁面、訪客結果頁、分享報告頁、登入流程的頁面，一律不讓搜尋引擎收錄。
4. 每個公開頁面有自己的標題和一兩句描述，用家屬會打的字。既有頁面只改標題與描述，內文不動。
5. 每個公開頁面有貼到 LINE 時的預覽（標題、描述、圖片）。
6. 加自動檢查（比照 `test_standards.py`）：公開頁面都有標題與描述、都在 sitemap；不公開的頁面都不在 sitemap。
7. 健康資料頁面禁止快取的規則（#182）不受影響。

先研究再提案：
- LINE 貼連結時讀哪些標記、圖片尺寸與大小限制，附官方來源。
- 預覽圖全站一張，還是重點頁面各一張（聽損模擬最可能被分享）。
- `qa/search`、`qa/results` 該不該被收錄。

要問我：
- 每個既有頁面的新標題與描述：請依上面五句話列一張建議表，我逐列確認。
- 預覽圖的設計（我在設計圖挑）。

要我做的：在 Google Search Console 提交 sitemap（請告訴我網址和步驟）。

驗收：sitemap 列的網址都回 200、都不用登入；不公開的頁面帶禁止收錄標記；我把首頁、家人專區、聽損模擬貼到 LINE，預覽正確。

1. 新增「關於聽伴」頁，不用登入：誰做的、內容怎麼查核、資料怎麼處理的重點、不能取代檢查。文字我寫。
2. 意見回饋入口每頁頁尾都找得到，不用登入，不強制留聯絡方式。
3. 回饋的文字可能含健康資料或個資：保存期限與清除方式比照問句紀錄（ADR 0034），並寫進隱私權說明。
4. 回饋入口要有速率限制，沿用訪客算分那套認來源的方式（`NUM_PROXIES`）。

先研究再提案：回饋存自己的資料庫，還是直接寄到我的信箱（沿用 Resend）。比較隱私、維護成本、被濫用時的後果。

要問我：

- 回饋保存多久。
- 隱私權說明這次的修改要不要升同意書版本；要的話併到第 4 項。

驗收：兩者不用登入可用；回饋送出後我收得到；連續大量送出會被擋；隱私權說明寫到回饋怎麼保存。

## 第 4 項：email 重測提醒

可沿用：Resend 寄信（#355）、`main_flow.py` 的下次建議日期與是否到期、systemd timer 的做法。

已決定：
1. 只寄給明確勾選要收提醒的人，預設不寄。
2. 沒有 email 的帳號不寄，設定頁說明要先填 email。
3. 每一次到期只寄一封，不追加催促信。
4. 信裡不寫分數、分級或任何健康資料，只說可以再做一次並附連結。
5. 每封信有一鍵取消的連結，不用登入就能取消。
6. 同一次到期不會重複寄：排程重跑、中途失敗重試都一樣。
7. 寄不出去送 Sentry，不影響其他人的信。
8. 隱私權說明寫明 email 會用於提醒。這裡升同意書版本，第 3 項如果也要升就一起。

要問我：
- 在哪裡問「要不要收提醒」：結果頁、保存後，還是帳號設定。
- 到期當天寄，還是提早幾天。
- 信的主旨與內文（我寫）。
- 排程一天跑一次，跑在什麼時間（要跟 02:30 清問句紀錄、03:00 備份錯開）。

請在規格裡說明：一鍵取消的連結怎麼做，才不能被別人拿來取消他人的提醒。

驗收：沒勾選的人收不到；同一次到期排程連跑兩次只寄一封；取消後不再收到；改別人的連結取消不了別人的；信裡沒有健康資料。

## 第 5 項：三個家屬頁面、兩個入口、「傳給他」

### 三個新頁面（放家人專區，不用登入）

| 頁面 | 對應的原話 | 結尾帶去哪 |
|---|---|---|
| 怎麼知道爸媽的聽力變差了 | 我爸媽的聽力還好嗎？ | 傳給他做篩檢 |
| 看電視開很大聲怎麼辦 | 看電視都要開很大聲，受不了 | 傳給他做篩檢 |
| 為什麼他一直說「蛤」 | 為什麼跟他講話都一直蛤？ | 聽損模擬，再到「怎麼跟聽損的家人說話」 |

已決定：
1. 內文與出處由我寫、我審定。沒有我審定的文字，頁面不上線。請先給我每頁的空白骨架（要我填哪幾段），我填完再做。
2. 只在有依據時下判斷（ADR 0017）：列出值得留意的情況，不替家屬判定長輩有沒有聽損，結尾導向篩檢或就醫。
3. 每頁有「本頁資料查核於」日期與出處，加進每年查核的清單。
4. 急症提醒沿用問答小助手現有的寫法。
5. 版面沿用家人專區現有元件，不新增元件。三頁都進 sitemap。

### 兩個入口

已決定：
1. 未登入首頁第一眼分成兩個門：「我想了解自己的聽力」→ 開始篩檢；「我擔心家人的聽力」→ 家人專區。
2. 已登入的首頁（照顧旅程，ADR 0044）不動。
3. 匿名月計數加兩個數字：兩個門各被按幾次。不存明細、不存 IP。

### 傳給他

已決定：
1. 家屬內容頁加明顯的「傳給他做篩檢」。傳出去的連結直接落在訪客可以開始篩檢的地方。
2. 連結不帶任何可以辨識家屬或長輩的資料。
3. 手機優先用系統的分享功能，沒有時退回現有的複製連結做法。

先研究再提案：
- 從 LINE 點開連結會開在 LINE 內建瀏覽器。長輩在那裡做完篩檢、之後想保存時，訪客流程走不走得通？
- 傳出去的訊息文字能不能預先帶好。

要問我：
- 兩個門的文字、圖示與排列（我在設計圖挑）。
- 「傳給他」的預設訊息。長輩收到時不該覺得被說有問題。
- 「傳給他」放在哪些頁面。
- 「怎麼知道爸媽的聽力變差了」用條列，還是做成可以勾的清單（勾了不計分、不存）。
- 家人專區首頁怎麼排這三頁。

驗收：三頁不用登入可開、200% 字級不左右捲動、出處與查核日期都在；未登入首頁兩個門各到對的地方；iPhone 上按「傳給他」跳出分享選單，傳到 LINE 預覽正確；我請家人點開連結，不用註冊就做完 HHIE-S 看到結果。

## 第 6 項：診間 QR code 小卡

目的：我在診間當面把聽伴交給病人和家屬。這是最快拿到真實使用者的方法。

已決定：
1. 做一個可以直接列印的小卡頁面（不用登入、不進 sitemap），印出來裁開就能用。
2. 兩種卡：給長輩本人的（掃了直接開始篩檢）、給家屬的（掃了到家人專區）。
3. 卡上的字要大，寫清楚掃了會看到什麼、不用註冊、免費。
4. QR code 的連結帶一個來源標記，匿名月計數多一格「從小卡進來」。不存明細、不存 IP。
   注意：訪客保存頁已經在用 `?from=card` 表示「從保存卡來」，新的參數請用別的名字，不要撞。
5. QR code 在自己的伺服器產生，不呼叫外部服務。

要問我：
- 卡片尺寸（名片大小或 A6）與一張 A4 排幾張。
- 卡上要不要放我的姓名或單位，還是只放聽伴。這題跟「關於」頁那一題一起決定。
- 卡上的文字（我寫）。

驗收：我印一張出來，用 iPhone 和一支 Android 手機掃得到、落在對的頁面；月計數那一格有加一。
