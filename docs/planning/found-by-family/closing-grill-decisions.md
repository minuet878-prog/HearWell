# 「讓家屬找得到」第 1 項：收尾　拷問決定（2026-11-16）

起點是[規劃](plan.md)的第 1 項和[外部監控研究](monitoring-research.md)；這裡記本人拷問時的決定，跟規劃不同的以這裡為準。

## 拷問前查到的事實

- Mac 的 `~/backups/hearwell-vps` 最新一份停在 2026-11-06，之後 10 天沒拉；手動備份 `hearwell-before-0029.dump` 還在。Mac 上沒有備份排程。
- Mac 的 SSH 金鑰放在鑰匙圈，排程可以自己連 VPS。
- 筆記寫的「保留 7 天」和 ADR 0042 的「刪除超過 8 天的」是同一件事（`find -mtime +7`），跟 VPS 一樣。
- #525 在 `docs/verification/issue-355.md` 已有 2026-11-14 的完成紀錄；同一天稍晚 `.env` 又為 Google、LINE 登入改過。
- #492 合併的那一包（`001fb85`）改了 73 個檔、約 5,200 行；之後其中 38 個檔被 Google、LINE 登入改過（各自做過交叉審查）。
- 沒登入的首頁不讀資料庫，站上也沒有「不用登入又會讀資料庫」的公開頁面：監控查首頁的話，資料庫掛掉不會響。

## 決定

| # | 題目 | 決定 | 跟規劃不同 |
|---|---|---|---|
| Q1 | Mac 怎麼拉備份 | launchd 排程：登入時跑一次、每天再跑一次；先 `rsync` 拉回來，再刪舊檔 | |
| Q2 | VPS 連不上時刪不刪舊備份 | 拉成功才刪超過 8 天的。VPS 連不上的期間不刪，那段時間 Mac 上的備份可能超過 10 天（ADR 0042 補一句） | |
| Q3 | 備份這條鏈斷了怎麼知道 | 「拉失敗」或「最新一份超過 2 天」時，Mac 跳桌面通知並寫一行紀錄；不經過第三方 | 規劃沒寫 |
| Q4 | 還原到哪裡 | Mac 的 Docker Postgres，另建測試資料庫；用新排程拉回來的最新一份；驗證完刪掉 | |
| Q5 | 驗證到什麼程度 | 比對數字（問卷數、最新 migration、使用者數、作答筆數，跟正式站比），再讓本機網站暫時接上還原的資料庫，用本人的正式帳號登入、打開我的紀錄 | |
| Q6 | 還原文件放哪 | `docs/deployment/restore.md`，進版控；主機位址、帳號寫代稱，開頭列「真的值去哪裡查」 | |
| Q7 | 還原文件寫多少 | 兩段：「演練」寫到照做不用猜；「真的出事時」只列順序（開新主機 → 照 VPS 筆記部署 → 還原資料 → 改網域指向），標明沒演練過 | |
| Q8 | 定期演練 | 每年 10 月一次（跟內容查核排一起）；Postgres 升大版本或換 Mac 之後也做；寫進 roadmap 時間型待辦 | 規劃沒寫 |

| Q11 | 外部監控用哪家 | Sentry Uptime（已在用、不新增第三方；只有 email，iPhone 的 Gmail 通知要打開） | |
| Q12 | 監控查哪個網址 | 新增「運作檢查」網址：碰一下資料庫，正常回 200、連不上回 503；不收資料、不進 sitemap、不讓搜尋引擎收錄 | 規劃沒寫要寫程式 |
| Q13 | 停機測試 | Gunicorn 和 PostgreSQL 各停一次，各等到收信再恢復 | 規劃只寫停服務 |

## 代理定的（本人確認）

- 每天那一次排在中午 12:00；Mac 在睡眠的話醒來時補跑。
- 本人要做的清單（建 Mac 排程、刪手動備份、還原演練、設定 Sentry、停機測試）跟還原文件一樣進版控、用代稱。
- 手動備份＝檔名不是 `hearwell-db-日期.dump` 的備份檔；VPS 和 Mac 都由本人照清單刪。
- 「運作檢查」不做交叉審查（不收資料、不涉及登入與計分），做自審。
- 順序：Mac 排程 → 刪手動備份 → 還原演練；運作檢查上線 → 設定 Sentry → 停機測試；#492 審查同時進行。
- roadmap 上過時的「上線前本人要做 #525」在收尾時改掉。
