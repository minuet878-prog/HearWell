# 實作計畫：聽力圖第 2 批（修改、比較）

規格：`docs/specs/phase-05/phase5_audiogram_2.md`　分支：`feat/audiogram-2`

## 一、修改

### 後端
- **`screening/api/views.py`**：`AudiogramDetail` 加上 `PUT /api/audiograms/{id}/`（整張取代）。
  - 只從 `request.user.audiograms` 找，別人的回 404（沿用 `_own_audiograms`）。
  - 驗證直接用第 1 批的 `AudiogramCreateSerializer`（同一套點的規則、日期規則），不另寫一份。
  - 存檔在一個 transaction 裡：改日期 → 刪舊點 → 寫新點。任何一步失敗就全部回復（驗收 3、6）。
  - **不需要收據編號**：PUT 是「整張換成這個內容」，送兩次結果一樣，連按兩次不會重複（驗收 7）。（PUT 的這個特性叫「冪等」：做一次和做很多次結果相同。）
  - 不開放 PATCH（部分修改），只收整張。
- **`screening/views.py`、`urls.py`**：新增 `GET /audiograms/<id>/edit`，`@login_required`、只找自己的。
- **template**：修改頁沿用 `audiogram_new.html`（標題、說明依新增／修改切換），把原本的點和日期用 `json_script` 放進頁面給 React 讀；`audiogram_detail.html` 加「修改」按鈕。

### 前端
- **`AudiogramApp.jsx`**：多三個選填 props：`audiogramId`、`initialPoints`、`initialTestedOn`。
  - 有 `audiogramId` 時：打開就帶入點和日期；存檔改送 `PUT /api/audiograms/{id}/`、不帶收據編號；回 404 時顯示「這張聽力圖已經不存在」。
  - 「最後標的點」一開始是空的，所以清除鈕自然不能按（驗收規格 4.1 清除按鈕）。不用另寫判斷。
- **`audiogram-main.jsx`**：讀頁面上的 `json_script`，有就傳進去。

## 二、比較

### 後端
- **`screening/audiogram.py`**：新增 `compare(new_points, old_points)`，不碰 Django。
  - 每耳：四頻平均、程度，**兩張都呼叫既有的 `interpret()`**（就是 `Audiogram.interpretation()` 用的那一個），差值＝新平均 − 舊平均；任一張資料不足 → 差值 `None`（畫面「—」）；任一張四頻含無反應 → 加註。
  - 逐頻率（氣導、骨導分開）：舊點、新點、差值。任一邊沒有值 → 差值「—」；任一邊無反應 → 「無法比較」；其他 → 新 − 舊（0、-10 照常算）。
  - **只列至少有一張有值的頻率**；兩張都沒標的頻率不出現（待確認 1）。
- **`screening/views.py`、`urls.py`**：新增 `GET /audiograms/compare?new=…&old=…&ear=right`（參數名稱實作時定）。
  - 沒帶參數 → 預設最新一張與前一張。
  - 參數裡的 id 不是自己的、或不存在 → 404（驗收 18）。
  - 兩個 id 相同 → 顯示「請選兩張不同的聽力圖」。
  - 新舊依「檢查日期、同一天看先後存」排序決定，跟哪個選單無關（驗收 11）。
  - 少於兩張時直接打開網址 → 顯示「要有兩張聽力圖才能比較」，不回錯誤頁。
- **新 template `audiogram_compare.html`**：
  - 兩個下拉選單＋「比較」按鈕（一般網頁表單，用 GET 送出，不需要 JavaScript）。
  - 「右耳／左耳」切換鈕：做成兩個連結，按了重新載入頁面、網址帶 `ear=`（待確認 2）。
  - 對照表由 Django 直接輸出（四頻平均列＋氣導表＋骨導表），差值寫「+15」「-10」「0」。
  - 圖：交給 React 畫（見下面）。
- **`audiogram_list.html`**：上方加「比較聽力圖」；少於兩張時是不能按的按鈕，旁邊寫原因。
- **比較沒有 API**（待確認 3）：跟檢視頁一樣由 Django 輸出，資料不出 `request.user` 的範圍。規格第 3 節「頁面與 API 都要有 404 測試」，比較只有頁面，所以只測頁面。

### 前端
- **`AudiogramChart.jsx`**：多一個選填 prop `oldPoints`。舊的點用同耳色的淡色（右 `#e8a59d`、左 `#9db5d6`，跟比較頁 A3 一樣）、虛線連線，先畫舊的、再畫新的（新的蓋在上面）；圖下方加圖例（線段樣式＋日期）。沒傳 `oldPoints` 時跟現在完全一樣。
  - 淡色只用來畫舊的線和符號；日期、數字都在 HTML 的圖例和表格裡，不靠淡色的字傳達資訊（對比度不夠）。
- **`audiogram-view-main.jsx`**：頁面上有舊點的 `json_script` 就一起傳；比較頁沿用這個進入點，不新增進入點、不增加下載量。

## 待確認

1. **對照表只列有值的頻率**：兩張都沒標的頻率不出現在表裡。另一種是氣導固定列 8 個頻率、骨導 4 個，沒值的寫空白。建議只列有值的，表比較短，手機上好讀。
2. **左右耳切換用連結（重新載入頁面）**：好處是不需要多寫 JavaScript、上一頁會回到另一耳、網址可以直接打開某一耳。代價是切換時整頁重新載入（約半秒）。另一種是用 JavaScript 切換、不重新載入，但對照表也要改成 React 畫，前端工作量多一倍。建議用連結。
3. **比較不做 API**：只做 Django 頁面。之後如果要把比較頁 React 化或做 PWA 離線，再補 API。建議不做（規格沒要求、少一個要保護的入口）。
