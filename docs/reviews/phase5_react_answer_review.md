## 發現

### F1. 重新整理之後，瀏覽器「上一頁」會跑到舊的題目，不會離開作答頁　【嚴重度：中】

- **位置**：`frontend/src/AnswerApp.jsx:34-40`（`begin`）
- **問題**：`begin()` 只把「目前這一格」歷史紀錄改成第 0 步（`replaceState`），沒有處理**重新整理之前留下的舊紀錄**。例如答到第 4 題時重新整理，瀏覽器歷史裡還有舊的「第 0、1、2、3 步」，排在目前這一格前面。重新整理後就算回到助聽器題（第一頁），再按上一頁也不會離開，而是跑到舊的「第 3 步」。
  - 規格 4.1「在第一頁按才離開作答頁」、第 5 節驗收條件「在第一頁按瀏覽器上一頁，則離開作答頁」，在重新整理過之後就不成立了。驗收條件「答到第 4 題時重新整理」正好就是這個情境。
  - 真的瀏覽器裡，那些舊的紀錄屬於重新整理前的頁面，所以按上一頁很可能會**整頁重新載入**，又出現一次「要接著答嗎？」，而且 `begin()` 會再把歷史改寫一次。使用者要連按好幾次上一頁、看到好幾次重新載入才離得開。對 65 歲以上的使用者來說很容易困惑。
  - 停在「要接著答嗎？」畫面時按上一頁，`onPopState` 因為 `form` 是 null 直接忽略，畫面完全沒有反應（jsdom 是測試用的模擬瀏覽器，在 jsdom 裡是這樣；真的瀏覽器可能是整頁重新載入）。
  - 送出成功、到結果頁後按上一頁回到作答頁（重新載入的情況），也會碰到一樣的舊紀錄。
- **能否重現**：實際跑過（jsdom）。答到第 4 題 → 模擬重新整理（保留歷史，`history.state` 是 `{"answerStep":4}`）→ 按「接著答」→ 按 4 次「上一題」回到助聽器題 → 再 `history.back()`，結果畫面變成 **「第 3 題／共 10 題」**，`history.state` 是 `{"answerStep":3}`，沒有離開。
  - 現有的測試沒抓到，是因為測試的 `reload()` 只把目前這一格清成 `null`，沒有模擬「前面還有舊紀錄」。（真的瀏覽器裡到底是 popstate 還是整頁重新載入，要人工驗收確認，但兩種都不符合規格。）
- **建議**：載入時如果 `history.state?.answerStep` 已經是大於 0 的整數 k，代表前面還有 k 格這一頁的舊紀錄，要先處理掉，例如把這 k 格當作現成的第 0～k 步沿用，不要再往後疊。改完把測試的 `reload()` 改成保留舊歷史，並加上「重新整理 → 接著答 → 一路上一頁到第一頁 → 再上一頁 → 離開」的測試。這部分牽涉真的瀏覽器怎麼處理跨頁面的歷史紀錄，**建議先在手機和桌機的瀏覽器人工確認現象，再決定修法**。

### F2. 草稿的 `answers` 是 null 或缺少時，按「接著答」整頁變空白，Django 表單也已經藏起來了　【嚴重度：中】

- **位置**：`frontend/src/draft.js:35`（`draft.answers ?? {}`）、`frontend/src/AnswerApp.jsx:16`（`hasAnything`）、`:115`
- **問題**：`isUsable` 用 `draft.answers ?? {}` 檢查，所以 `answers: null` 或沒有 `answers` 這個欄位都會被當成「可以用」。按「接著答」之後，`hasAnything` 執行 `Object.keys(null)` 拋出 TypeError；React 沒有錯誤邊界（error boundary，接住畫面錯誤的機制），整個作答畫面被卸掉。這時 `onReady` 已經把 Django 表單設成 `hidden`，**頁面上什麼都沒有，沒辦法作答**。違反規格 4.2「資料壞掉 → 當作沒有紀錄」和驗收條件「頁面不壞」，也違反「`main` 隨時可用」的精神。
- **能否重現**：實際跑過。localStorage 放 `{userId:7, questionnaireId:1, key:"k", wearing:null, answers:null, step:0, savedAt:現在}` → 按「接著答」→ `TypeError: Cannot convert undefined or null to object`，`document.body` 只剩 `<div></div>`。
- **建議**：`isUsable` 要求 `answers` 一定是物件，例如把 `draft.answers ?? {}` 改成 `draft.answers` 並先檢查 `typeof draft.answers === "object" && draft.answers !== null && !Array.isArray(draft.answers)`。在 `draft.test.js` 的 `it.each` 加「answers 是 null」「沒有 answers」兩種情況。

### F3. 收到 409 之後按瀏覽器上一頁，已經清掉的草稿又被存回去　【嚴重度：低～中】

- **位置**：`frontend/src/AnswerApp.jsx:70-72`（存草稿的 effect）、`:59-68`（popstate）
- **問題**：收到 409 時會清掉草稿、顯示「這份作答之前已經送出過」。但這時 `form` 還在，使用者按上一頁會觸發 `popstate` → `setForm` → 存草稿的 effect 又把草稿（包含**已經用過的收據編號**）寫回 localStorage。下次打開作答頁會問「要接著答嗎？」，接著答再送出又是 409。這違反規格「409 時清掉保留的答案」的用意。
- **能否重現**：實際跑過。409 之後 `localStorage` 是 `null`；`history.back()` 之後變成 `{"key":"32f5…","wearing":false,…}`。
- **建議**：狀態是 `duplicate` 時不要存草稿（例如 409 時把 `form` 設成 null，或在存草稿的 effect 裡判斷狀態）。補一個測試：「409 → 上一頁 → 草稿仍是 null」。

### F4. 送出中可以按「上一題」、改答案，送出按鈕會重新變成可按，送出第二次　【嚴重度：低】

- **位置**：`frontend/src/AnswerApp.jsx:120-123`（`choose` 會把狀態設回 idle）、`:217-221`（送出中「上一題」沒有停用）
- **問題**：送出中按「上一題」→ 改一個答案 → `choose()` 把狀態從 `sending` 改回 `idle` → 回到最後一題，「送出」按鈕可以按了（文字也從「送出中…」變回「送出」）→ 用同一個收據編號、不同的內容送第二次 → 伺服器回 409，畫面變成「之前已經送出過」並清掉草稿；第一次的請求成功之後又會跳到結果頁。資料庫不會存成兩筆（有收據編號保護），但畫面會亂跳。
- **能否重現**：實際跑過。送出後「上一題」→ 第 9 題改選「有時」→「下一題」→ 按鈕文字「送出」、`disabled: false`，按下去 POST 變成 **2 次**。
- **建議**：送出中把「上一題」和選項也停用，或者 `choose()` 不要把 `sending` 改掉。發生機率很低（要在回應回來之前的短時間內操作），可以跟 F1 一起處理。

### F5. 一打開作答頁焦點就移到題目，螢幕閱讀器會跳過問卷名稱和說明　【嚴重度：低】

- **位置**：`frontend/src/AnswerApp.jsx:37`（`begin` 設 `moved.current = true`）、`:74-77`
- **問題**：沒有草稿時，載入完成就呼叫 `begin()`，焦點直接移到助聽器題，使用者這時還沒有任何操作。規格寫的是「換頁後焦點移到題目」。螢幕閱讀器使用者可能聽不到問卷名稱、題數和說明（它們在 React 畫面上方）。按「接著答」或「重新開始」之後把焦點移到題目是合理的，那是使用者自己操作的結果。
- **能否重現**：實際跑過。沒有草稿時，載入後 `document.activeElement` 是 `LEGEND`。
- **建議**：第一次載入（不是使用者按了按鈕）時不要移焦點。這要配合人工驗收的「螢幕閱讀器」那一條一起確認，**由你決定**。

### F6. 錯誤訊息換頁後還留著　【嚴重度：低】

- **位置**：`frontend/src/AnswerApp.jsx:208`
- **問題**：最後一題出現「送出失敗，請再按一次送出」之後按「上一題」，第 9 題下面還是顯示「送出失敗，請再按一次送出」（`role="alert"`），可是第 9 題沒有送出按鈕。「還有 n 題沒有回答」跳到漏答的題目時，留著是對的；但送出失敗、400 的訊息留在其他題目會讓人困惑。
- **能否重現**：實際跑過，第 9 題的 alert 是「送出失敗，請再按一次送出」。
- **建議**：只在最後一題顯示送出相關的錯誤，或換頁時清掉（漏答提示除外）。小事，可以不改。

### F7. 測試沒有真的驗到：換頁後焦點移到題目　【補測試】

- **位置**：`frontend/src/AnswerApp.test.jsx:127-135`
- **問題**：突變驗證時，把 `goNext` 裡的 `moved.current = true` 拿掉（換頁後就不會移焦點），測試**仍然通過**；把 popstate 裡的 `moved.current = true` 拿掉（上一頁後不移焦點），也**仍然通過**。原因是：載入時 `begin()` 已經把焦點放在 `<legend>`，`fireEvent.click` 不會把焦點移到按鈕上，而且 React 換頁時沿用同一個 `<legend>` 元素，所以焦點本來就一直在那裡。
- **建議**：按「下一題」前先把焦點放到按鈕上（`button.focus()`，模擬真的點擊），再斷言焦點在 legend；上一頁（popstate）也加一個同樣的斷言。

### F8. 測試沒有真的驗到：「接著答」時補回上一頁的歷史紀錄　【補測試】

- **位置**：`frontend/src/AnswerApp.test.jsx:295-317`、`AnswerApp.jsx:36`
- **問題**：突變驗證時把 `begin()` 裡補推歷史紀錄的那一行（`for … pushState`）刪掉，「接著答後所有答案都在」的測試**仍然通過**。原因跟 F1 同一個：測試的 `reload()` 留著重新整理前的舊歷史紀錄，`history.back()` 剛好碰到舊的「第 3 步」，誤打誤撞過關。
- **建議**：修 F1 時一起改 `reload()`，讓這個測試真的依賴 `begin()` 補推的紀錄。

### F9. 收到 403 一律說「登入已經過期」，CSRF token 過期也一樣　【嚴重度：低】

- **位置**：`frontend/src/AnswerApp.jsx:173-174`、`answer-main.jsx:13`
- **問題**：CSRF token（防止別的網站冒用你身分送出的驗證碼）從頁面上的 hidden input 讀。如果使用者在另一個分頁重新登入過（登入時 token 會換新），這一頁送出時會收到 403「CSRF Failed」，畫面顯示「登入已經過期，請重新登入」。照著按登入、登入完回到作答頁、接著答，就能正常送出，所以結果是對的，只是訊息不完全準確。
- **能否重現**：從程式推論出來的，沒有實際跑（要真的 session）。
- **建議**：不改。走的流程結果正確，改成讀 cookie 反而要多寫程式。

### F10. bundle 大小量的方式　【確認沒問題】

- `bundle.test.js` 在記憶體裡用 production 模式建置，從 `answer` 入口沿著靜態 import 一路加總每個檔案的 brotli 大小。正式環境 `requirements.txt` 有 `brotli`，whitenoise 會送出 brotli 檔，所以**這樣量就是使用者實際下載的大小**。實測約 60.9 KB。
- 沒有算進去的部分：作答頁同時還會載入 `logout.js`（0.08 KB，它用的 draft 那個檔已經算在裡面了），差別可以忽略。
- 突變驗證：只寫 `import "recharts"`（只引入、沒有用）時測試會通過，因為沒用到的程式在建置時會被刪掉（tree-shaking），本來就不會被下載；改成真的用到 `LineChart` 時，測試**正確失敗**。

### F11. logout.js 載入的時間點　【確認沒問題】

- `layout.html` 在 `<head>` 用 `type="module"` 載入，module 腳本預設會等 HTML 解析完才執行，所以 `#logout-form` 一定已經存在。`logout.js` 只引入 draft 那個檔（0.45 KB），**不會**讓每個登入後的頁面都下載 React。

### F12. Django 表單和 React 並存　【確認沒問題，有一個小提醒】

- API 載入失敗時不呼叫 `onReady`，表單不會藏起來（有測試）；JS 沒載入時表單完整、可以送出（Django 測試有實際 POST）。IOI-HA 不載入 `answer.js`。
- 小提醒：React 已經接手之後，只要畫面出錯（例如 F2），表單就已經藏起來了，沒有退路。目前只有 F2 會觸發這種情況，修掉 F2 就夠了，**不建議**另外加錯誤邊界（多寫）。

### 其他確認過、沒有問題的項目

- 驗收條件第 5 節，自動化的 25 條在測試裡都有對應。「分數和網頁版一樣」「全選從未 → 總分 0、最輕一級」「只存一筆」的後端部分，由 Phase 5 第 1 項既有的 `ApiSubmitTests` 驗證（`test_valid_submission_is_saved_and_scored`、`test_all_zero_is_a_real_score`、`test_same_key_same_body_returns_first` 等），前端測試只驗送出的內容，分工合理。
- 突變驗證**會失敗**（測試有效）的有：拿掉跳到漏答題、成功後不清草稿、送出中不停用按鈕、第一頁改用 pushState、409 不清草稿、拿掉漏答檢查、每次送出都換新收據編號、不刪別人的草稿、拿掉 step 上限檢查。
- 換帳號：`loadDraft` 打開任何一份作答頁時，會把不屬於自己的**所有**草稿刪掉（有測試）；登出時全部清掉（有測試）。其他帳號不會看到答案。
- 無痕模式：所有 localStorage 存取都包在 try/catch 裡（有測試）。
- 多寫：沒有發現多餘的抽象或設定。`hasAnything`（沒有作答就不存草稿）、`DRAFT_PREFIX`／`MAX_AGE_MS` 匯出給測試用，都合理。
- `answer_compare.html`（比較頁）還在 repo 根目錄、沒有進版控，記得在第 9 步收尾時刪掉。
- 規格檔狀態目前是「實作中」，第 5 節人工驗收 5 條還沒打勾，這是預期中的。
