## 發現與分類

### 1-1 螢幕閱讀器不一定會「主動」唸出「題目載入中…」 → **補測試（人工）**

- 位置：`screening/templates/screening/screening.html` 的 `#answer-loading`
- 問題：`role="status"` 會播報「後來的變化」；這段文字是元素一建立就寫進去，多數螢幕閱讀器不會主動播報。但文字在畫面上、位置在說明下方，照順序往下讀會讀到。jsdom 測不出「有沒有唸」。
- 查證：程式碼確認文字是元素建立後立刻寫入（同一段 inline script）。實際播報需要真的螢幕閱讀器才能驗。
- 理由：規格的意思若是「讀得到」就已符合；若要「一進頁面就主動播報」，要另外討論做法。

### 1-2 太晚拿到題目時，React 拆掉前已經改了瀏覽器的上一頁紀錄 → **不改**

- 位置：`frontend/src/AnswerApp.jsx` 的 `begin()`（在 `onReady()` 之前執行）
- 查證：程式碼確認 `begin()` 會 `history.replaceState`，紀錄裡已有作答步驟時還會 `history.go`。都在同一頁內，不會離開頁面；表單和已選答案不受影響（驗收 5 的測試有驗）。
- 理由：要同時「載入超過 5 秒＋沒有草稿＋從之前的作答步驟回來」才會發生，影響只有上一頁按鈕的位置；要修得改 `AnswerApp` 的載入流程，超出範圍。

### 1-3（原本就有）網頁表單送出驗證失敗後，React 會接手、蓋掉錯誤訊息 → **不改，記進 roadmap**

- 位置：`screening/views.py` 的 `screening`（驗證失敗時帶著錯誤重新顯示同一頁）＋ React 作答頁
- 查證：程式碼確認驗證失敗會 `render` 同一個 template；template 一樣載入 React，React 拿到題目就接手、從第 0 步開始，錯誤訊息和已選的答案看不到。修改前 React 載入完也會藏表單，不是這次造成的。
- 理由：規格「不做」：不改動一題一頁的作答流程。只有網頁表單（備用）送出失敗才會遇到。
