# 審查結果：PWA 返回鍵與下拉重整

規格：`docs/specs/phase-10/phase10_pwa_back_refresh.md`　審查：`reviewer` subagent（2026-10-18），由主 session 逐項查證。

## 要修

1. **作答頁按「上一頁」被帶回首頁**（已重現）
   - 作答頁每進一題都用 `pushState` 新增一筆瀏覽紀錄（`AnswerApp.jsx:45`、`:135`），舊版表單的錨點連結也會新增。
   - 在同一份網頁裡退回不會發出 `pagehide`，0.5 秒的計時器照樣觸發，畫面被帶去首頁。
   - 暫存腳本重現：`history.back()` 之後接著 `assign("/")`。
2. **網路慢時，正常的上一頁也會被改成跳首頁**（未實際重現，依瀏覽器行為推論）
   - 上一頁不是從快取還原時，要等伺服器回應新頁面，`pagehide` 才會發出。Render 伺服器剛從休眠醒來時常超過 0.5 秒，計時器會先把畫面帶去首頁。
   - 要改的是判斷方式，需要本人決定（見下）。
3. **兩指縮放時誤觸重新整理**（已重現）
   - 只看第一根手指，沒有檢查是不是多指觸控。暫存腳本重現：兩指觸控、第一根手指往下移超過 80px，放開就 `reload()`。
   - 修法：碰到螢幕時有兩根以上手指，或畫面已經放大（`visualViewport.scale > 1`），就不啟動下拉；拉到一半有第二根手指加入時，取消這次下拉。

## 補測試

- 9／9b 用真實頁面驗證：規格列的 8 頁 `<main>` 裡都有表單欄位（聽力圖輸入頁改成確認有 React 掛載點），我的紀錄頁沒有。寫在 Django 樣板測試。
- 12 左右捲動：審查建議檢查整頁寬度 ≤ 320。但頁尾 email 在 200% 字級時本來就會撐寬（roadmap 已記，`main` 就這樣），整頁一定過不了。改成只檢查**標題列**的 `scrollWidth ≤ 320`。
- bug 1、3 各補 Vitest。

## 不改

- 規格狀態寫「實作中」：流程是「已確認」之後才開始實作，實作中把狀態改成「實作中」是範本允許的狀態，不影響流程。

## 待本人決定：bug 1＋2 的修法

| 選項 | 做法 | 代價 |
|---|---|---|
| A（建議） | 拿掉計時器。瀏覽器有 Navigation API（新的瀏覽紀錄功能）時，用 `navigation.canGoBack` 判斷能不能退回；沒有就用 `history.length > 1` | 不支援 Navigation API 的舊 iPhone，碰到「切回 app 時頁面被重新載入」之後的那個罕見情況，按上一頁會沒反應（還能按導覽列的首頁）。Safari 從哪一版開始支援要再查 |
| B | 保留計時器，另外監聽 `popstate`／`hashchange` 取消，時間拉長到約 5 秒 | 伺服器醒來超過 5 秒時仍會誤跳首頁，而且等待時間是猜的 |

## 處理結果（2026-10-18）

- 本人選 **A**：拿掉計時器，改用 `navigation?.canGoBack ?? history.length > 1`。
- bug 3：碰到螢幕時單指、沒放大才啟動；拉到一半第二根手指加入就取消。
- 補測試：Vitest 6 條（bug 1–3）、Django 4 條（9、9b；同意書頁要用還沒同意的帳號，已同意會被轉走）、e2e 標題列寬度。
- 結果：Vitest 180、Django 564、e2e 16，全部通過。
- 推上去後 CI 的 e2e 失敗：標題列寬度 349 > 320。根本原因是品牌字「HearWell」在 Linux 字型、200% 字級下本身就超過 320px（`main` 就這樣，不是上一頁按鈕造成）。本人選 A：拿掉標題列寬度檢查（驗收 12 由「上一頁按鈕在 320px 內、文字不截斷」守住），品牌字與底部分頁列記進 roadmap「200% 字級的左右捲動」。
