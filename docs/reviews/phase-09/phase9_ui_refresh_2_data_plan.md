# 前端設計重整 第 2 輪：實作計畫

規格：`docs/specs/phase-09/phase9_ui_refresh_2_data.md`（已確認）。第 4 步的計畫，等本人點頭才動手。

## 1. 趨勢圖（React，`frontend/src/`）

### `trend.js`（純資料，好測）
- `selectPoints`：每個點多三個欄位
  - `time`：從 API 的 `created_at`（已經是台灣時間，例如 `2026-10-15T14:30:00+08:00`）切出 `14:30`，不換算時區。
  - `sameDay`：同一份問卷裡，同一天有兩筆以上時為 `true`。
  - `unaided`／`aided`／`unrecorded`：依助聽器狀態，三個欄位只有一個是分數、其他是 `null`。三條線各讀自己的欄位。分數本身照 API 的 `total`，沒有重算。
- `summarize`：改照規格 4.2 的表，回傳 `{ date, statusText, total, levelText, change }`。「同一種狀態的上一筆」是往前找第一個 `wearing` 相同的點。

### `TrendChart.jsx`
- 一條 `<Line>` 換成三條：
  - 沒戴：實線。
  - 有戴：虛線（`strokeDasharray`）。
  - 未記錄：不畫線（`stroke="none"`），只畫點。
- 沒戴和有戴兩條線設 `connectNulls`（Recharts 的設定：中間遇到別種狀態的點時，跳過、接著連），所以只連同一種狀態的點。
- 點的形狀、分數標籤照舊，各自掛在自己的線上；最近一次照舊放大。
- 圖例改成「線段樣式＋點＋文字」。
- 橫軸：`sameDay` 的點，日期下面多一行時間。Recharts 的刻度可以自訂成兩行文字。提示框標題也一樣。
- 標題下加「分數越低，聽力對生活的影響越小。」
- **分級底色的邊界**：中間的分界畫在「這一級最高分 ＋ 1」（8 → 9、24 → 25）；最上面一級照舊到最高分。
  - 理由：HHIE-S 每題只有 0、2、4 分，總分一定是偶數，所以兩級中間就是「最高分＋1」。趨勢圖只畫 HHIE-S（規格「不做」HHIA-S 的圖），這是一行就能解決的寫法。
  - 代價：以後如果有總分會是奇數的問卷要畫趨勢圖，這裡要重新想。程式裡會寫註解，並寫測試鎖住。
  - 不改 API、不改門檻（`THRESHOLDS` 動了要先做版本號，這裡不需要動）。

## 2. 下方紀錄卡片（Django）

- `views.my_hearing`：在目前分頁的紀錄裡，算出「同一天有兩筆以上」的紀錄 id（用台灣時間的日期），傳給模板。
- `my_hearing.html`：這些卡片的日期後面加 `H:i`。

## 3. IOI-HA 圖（Django 模板＋CSS）

- 格線原本是 CSS 背景漸層，畫在每一列的上緣。改成每一列放一條真的線（`<i class="ioi-line">`，跟點一樣用 `grid-row` 定位、垂直置中），數字、點、菱形本來就在列的正中間，所以會落在線上。
  - 不再用漸層，是因為漸層畫出的線在瀏覽器裡量不到位置；改成元素之後，e2e 才能量「數字、點、線三者的中心差不到 1px」（驗收 12）。
  - 線在常模灰框底下，跟現在一樣被灰框蓋住。
- `ioi_ha_chart.html`：常模說明下面加「7 題都是分數越高，代表助聽器的效益越好。」（有常模、未分組都顯示）。
