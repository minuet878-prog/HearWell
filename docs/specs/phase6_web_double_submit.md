## 1. 目標

用網頁版作答（IOI-HA 一律是網頁版；HHIE-S／HHIA-S 在 JS 失敗時退回網頁版）時，
連按兩次「送出」、或網路慢時重按，**只存一筆**，使用者看到的是那一筆的結果。
**沒有 JS 也要有效**：網頁版本來就是 JS 失敗時的備用。

## 2. 範圍

### 要做
- 網頁版作答（所有問卷）送出時帶一個收據編號；同一個人、同一個編號只存一筆（沿用寫入 API 已有的收據編號機制）
- 同一張頁面再送一次（不論答案是否相同）都當成重複，轉到第一次那筆的結果頁，上方加說明
- 按下「送出」後的回饋：按鈕變成「送出中…」、暫時不能按；10 秒沒回應或按上一頁回到這頁時恢復（這部分要 JS；沒 JS 時伺服器端照樣防重複）
- 收據編號缺少或格式不對：照舊存檔，只是不防重複

### 不做
- 寫入 API、React 作答頁（已經有收據編號）
- 網頁表單驗證失敗後被 React 接手（審查 1-3，是 Phase 6 下一項）
- 聽力圖（API 已經有防重複）
- 清理正式資料庫裡過去可能已經重複的紀錄（不動真實資料）
- 其他頁面（登入、註冊等）的連按

## 3. 必須遵守的規則

- 一律遵守 CLAUDE.md「不可違反的規則」。
- 本 phase 特別注意：
  - 規則 8：收據編號只在同一個人的紀錄裡比對；別人的編號不能讓你看到別人的結果
  - 作答驗證仍然走既有的表單（formset），不另寫一份

## 4. 行為描述

### 4.1 網頁版作答送出

| 項目 | 內容 |
|---|---|
| 網址與方法 | 既有作答頁，POST |
| 誰可以使用 | 未登入：照舊導去登入　　已登入：本人　　能否存取他人資料：不能 |
| 第一次送出 | 照舊：存檔、轉到結果頁 |
| 同一張頁面再送一次、答案相同 | 不新增，轉到第一次那筆的結果頁 |
| 同一張頁面再送一次、答案不同 | 同上：不新增，轉到第一次那筆的結果頁 |
| 驗證沒過（漏答等） | 照舊：同一頁顯示錯誤，沒有存檔；改好再送，收據編號不變，存一筆 |
| 重新打開作答頁（不是按上一頁） | 新的收據編號，可以再作答一次（重測是正常使用） |
| 收據編號缺少、格式不對 | 照舊存檔、轉到結果頁，只是不防重複 |
| 轉到第一次那筆時 | 結果頁上方說明：「這份作答剛才已經送出，以下是那次的結果；要重新作答，請從『開始篩檢』進入。」 |

### 4.2 「送出」按鈕的回饋（有 JS 時）

| 項目 | 內容 |
|---|---|
| 按下「送出」 | 按鈕文字變成「送出中…」、暫時不能按；螢幕閱讀器會念出「送出中」 |
| 驗證沒過 | 頁面重新顯示，按鈕是一般的「送出」 |
| 10 秒沒有回應 | 按鈕恢復成「送出」、可以再按 |
| 按上一頁回到這頁 | 按鈕是一般的「送出」 |
| 沒有 JS | 按鈕不變；伺服器端照樣防重複 |
