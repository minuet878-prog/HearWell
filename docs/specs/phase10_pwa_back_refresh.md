## 1. 目標

從手機主畫面打開 HearWell（全螢幕模式）時沒有瀏覽器的工具列：iPhone 沒有「上一頁」，兩種手機都不能下拉重新整理。
補上這兩個動作，讓 65 歲以上的使用者在 app 裡也能「回上一頁」和「重新整理」，用起來跟在瀏覽器裡一樣。

## 2. 範圍

### 要做
- 全螢幕模式下，頁面上有一個看得到、有文字的「上一頁」按鈕。
- 全螢幕模式下，在頁面最上方往下拉，放開後重新整理目前頁面；拉的過程有看得到的提示。

### 不做
- 在一般瀏覽器分頁裡顯示這兩個功能（瀏覽器本來就有，2026-10-18 確認）。
- 另外放「重新整理」按鈕（2026-10-18 確認不放）。
- service worker、快取、離線頁（Phase 4 已決定不用）。
- 左右滑動手勢（例如從螢幕邊緣滑回上一頁）。
- 「下一頁」按鈕、麵包屑（顯示「首頁 > 我的紀錄 > …」的路徑列）。
- 改動既有頁面的內容、導覽列項目或版面（除了標題列放上一頁按鈕需要的位置）。
- 作答的中途儲存、草稿保存。
- 新增前端套件。

## 3. 必須遵守的規則

- 一律遵守 CLAUDE.md「不可違反的規則」。
- 本 phase 特別注意：
  - **第 13 條**：字級用 `rem`；按鈕可點範圍至少 44×44 CSS px（WCAG 2.5.5 建議值）。
  - JS 載入失敗時，頁面其他功能照常可用（漸進增強：沒有 JS 就只是沒有這兩個功能，不能壞掉）。
  - 螢幕閱讀器要唸得出「上一頁」按鈕的名稱。下拉重整是輔助功能，不是完成任何任務的必要步驟，所以不另做按鈕。

## 4. 行為描述

### 4.1 上一頁按鈕

| 項目 | 內容 |
|---|---|
| 出現在哪 | 只在全螢幕模式；每一頁都有，首頁除外 |
| 誰可以使用 | 未登入、已登入都有（登入、註冊頁也要有） |
| 按下去 | 回到上一個看過的頁面（跟瀏覽器的上一頁一樣） |
| 沒有上一頁時（例如從主畫面直接打開某頁） | 回到首頁 |
| 外觀與位置 | 箭頭＋「上一頁」文字的外框按鈕，放在藍色標題列左邊、「HearWell」前面（白色外框，配合藍底） |

### 4.2 下拉重新整理

| 項目 | 內容 |
|---|---|
| 出現在哪 | 只在全螢幕模式；頁面內容裡有表單的頁面不啟用（作答、聽力圖輸入、登入、註冊、同意書、分享報告、聽力圖比較、刪除確認）。標題列的「登出」按鈕不算 |
| 觸發條件 | 頁面已捲到最上方，手指往下拉超過一段距離後放開 |
| 拉的過程 | 頁面上方出現提示：拉不夠時「往下拉重新整理」，夠了時「放開重新整理」 |
| 拉不夠就放開 | 什麼都不發生，提示收回 |
| 頁面不在最上方時往下滑 | 正常捲動，不觸發 |

- **規格以外的決定**：
  - 上一頁判斷改用 Navigation API（審查 bug 1、2，本人選 A）：原本 0.5 秒計時器會在作答頁退回上一題、或伺服器慢時誤跳首頁。
  - 兩指觸控、畫面放大時不啟動下拉（審查 bug 3）。
  - 200% 字級只檢查標題列寬度：頁尾 email 本來就會撐寬（roadmap 已記）。
- **這次用到的新概念**（各用一句話解釋）：
  - `display-mode: standalone`／`navigator.standalone`：判斷網站是不是從主畫面以全螢幕打開；前者是標準（Android），後者是 iPhone 專用。
  - Navigation API `canGoBack`：瀏覽器直接回答「還能不能退回」，包含同一頁裡 `pushState` 加的紀錄。
  - 觸控事件的 `touches`：目前在螢幕上的每根手指；長度大於 1 就是多指（例如兩指縮放）。
  - `visualViewport.scale`：使用者用手指放大頁面的倍率，大於 1 代表正在放大檢視。
  - passive 事件監聽：告訴瀏覽器「我不會擋住捲動」，捲動才不會因為等 JS 而卡頓。
