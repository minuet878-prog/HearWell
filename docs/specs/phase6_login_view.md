## 1. 目標

登入目前是自己寫的流程，安全檢查（例如 `next` 只接受本站網址）要自己維護。改用 Django 內建的登入，由框架負責這些檢查，對使用者來說畫面與動線維持原樣。
同時修掉一個少見的 500：兩個人幾乎同時用同一個名字註冊時，後送出的人應該看到「名字已被使用」，而不是錯誤頁。

## 2. 範圍

### 要做
- 登入改用 Django 內建的登入流程。
- 登入的網址、畫面、文字、`next` 動線維持現狀；改變的只有：登入失敗後使用者名稱留在欄位裡，游標跟著移到密碼欄（驗收 14）。
- 同名註冊撞車時，顯示和一般同名一樣的錯誤，不 500。
- 順手：Phase 6 測試分資料夾（`phase6_tests_by_feature.md`）的驗收 6 打勾（CI 已在 PR #49 通過）。

### 不做
- 註冊不改用內建的 view（註冊已經用內建表單 `UserCreationForm`）。
- 登出不改（已經只收 POST）。
- 不加忘記密碼、改密碼、記住我、登入次數限制、驗證碼。
- 不改登入頁的外觀與排版。
- 不改 Django 內建訊息的「你」→「您」（roadmap 另一項）。
- 大小寫不同的兩個名字（例如 `Alice` 與 `alice`）同時註冊：資料庫只擋完全相同的名字，這種情況會建出兩個帳號。機率比同名撞車更低，這次不處理，記在 roadmap。

## 3. 必須遵守的規則

- 一律遵守 CLAUDE.md「不可違反的規則」。
- 本 phase 特別注意：
  - `next` 只接受本站網址（open redirect 防護：不能讓登入後被轉到別的網站），行為不能因為換成內建而放寬。
  - 登入失敗的訊息不能透露「這個帳號存不存在」：帳號不存在和密碼錯，訊息一樣。
  - 測試帳號、密碼一律用假資料。

## 4. 行為描述

### 4.1 登入

| 項目 | 內容 |
|---|---|
| 網址與方法 | `/login`，GET 顯示、POST 送出（其他方法 405，同現狀） |
| 誰可以使用 | 未登入：可以　　已登入：照樣顯示登入頁（可換帳號登入）　　能否存取他人資料：不涉及 |
| 顯示的欄位 | 使用者名稱、密碼、登入鈕、註冊連結（帶 `next`）；有 `next` 時顯示「請先登入……登入後會帶您回到剛剛的頁面」 |
| **不能**顯示的 | 密碼（失敗後密碼欄一律清空）；帳號存不存在 |
| 成功後 | 有站內 `next` → 轉到 `next`；沒有或是站外網址 → 首頁 |
| 失敗後 | 留在登入頁，顯示「使用者名稱或密碼錯誤」，`next` 保留，使用者名稱留在欄位裡；使用者名稱有值時游標在密碼欄，沒有值時在使用者名稱欄 |

### 4.2 註冊撞車

| 項目 | 內容 |
|---|---|
| 情境 | A 送出註冊、表單檢查「名字沒人用」通過；在存進資料庫前，B 用同一個名字註冊成功 |
| 現在 | A 看到 500 錯誤頁 |
| 改成 | A 留在註冊頁，使用者名稱欄顯示「一個相同名稱的使用者已經存在。」（跟一般同名註冊的訊息一樣），沒有建出帳號、沒有登入，已填的使用者名稱與出生年留著 |

- **改了哪些檔案、為什麼**：
  - `screening/urls.py`：`/login` 改接 `LoginView`，沿用 `screening/login.html`；`http_method_names=["get", "post"]`，因為 `LoginView` 繼承的 `ProcessFormView` 會把 PUT 當成 POST。
  - `config/settings.py`：`LOGIN_REDIRECT_URL = "index"`（內建預設是不存在的 `/accounts/profile/`）。
  - `screening/templates/screening/login.html`：表單有錯就顯示固定的「使用者名稱或密碼錯誤」；使用者名稱欄帶回輸入值；使用者名稱有值時 `autofocus` 在密碼欄，否則在使用者名稱欄。

- **規格以外的決定**：
  - 不是「名字被用走」的 `IntegrityError` 照樣丟出（沿用網頁作答的做法；測試 `test_other_save_clash_is_not_reported_as_name_taken`，拿掉判斷時會失敗，試驗過）。
  - 驗收 14 的空白送出：使用者名稱沒有值時，游標留在使用者名稱欄（依「哪一欄要先填」判斷）。
- **這次用到的新概念**（各用一句話解釋）：
  - `LoginView`：Django 內建的登入 view，附帶 `sensitive_post_parameters`、`never_cache`、`csrf_protect`，`next` 用和原本相同的站內檢查。
  - 檢查後再使用的競態（TOCTOU）：「檢查名字沒人用」和「存檔」中間有空檔，只有資料庫的唯一限制擋得住。
  - `transaction.atomic()` 存檔點：PostgreSQL 交易中一句 SQL 失敗後，後面的查詢都會被拒絕；存檔點讓失敗只退回這一步。
  - 模擬競態：包住 `is_valid()`，讓檢查照常通過，接著才建立同名帳號。
  - `try／except／else`：`else` 只在沒出錯時執行，`login()` 放在那裡，撞車時就不可能登入。
