## 1. 目標

使用者可以一次下載自己在 HearWell 的全部紀錄（帳號資料、同意紀錄、問卷作答與結果、聽力圖），
落實個資法第 3 條的「查詢、閱覽、製給複製本」，也為之後的刪除權（下載完再刪）鋪路。

## 2. 範圍

### 要做
- 下載入口：「我的紀錄」頁一個按鈕（主要入口），隱私權說明頁也放連結。按下去直接下載一個 JSON 檔。
- 檔案內容只包含登入者本人的資料，內容見 4.1。
- 隱私權說明頁補一句「你可以隨時下載自己的資料」，並指向下載入口。
- 還沒同意目前版本說明的使用者也能下載（同意閘門開一個例外）。

### 不做
- 給醫師看的易讀報告、PDF、圖表（那是 Phase 8 的 C3）。
- 匯入（把檔案傳回來還原資料）。
- 寄 email、背景排程、壓縮檔加密碼。
- 帳號／資料刪除（Phase 7 下一項）。
- 管理員替別人匯出。
- 選擇匯出範圍或日期區間（一律全部）。
- CSV、ZIP 或其他格式（只做 JSON）。
- 下載前再輸入一次密碼。
- 附上行動建議文字（之後改文案會跟檔案不一致；分級名稱已足夠）。
- React 版畫面、或新的 API endpoint（網頁連結就夠；React 頁面需要時直接連過去）。
- 改動既有的計分、分級、門檻。

## 3. 必須遵守的規則

- 一律遵守 CLAUDE.md「不可違反的規則」。
- 本 phase 特別注意：
  - 只查 `request.user` 的資料（規則 8）；網址不帶任何使用者或紀錄編號，從根本上沒有「指定別人」的入口。
  - 總分、分項分數、分級走 `Submission` 的計分方法（規則 10），不另寫聚合。
  - 0 分照實匯出為 0，不能變成空白（規則 11）。
  - 測試只用假資料（規則 3）。

## 4. 行為描述

### 4.1 下載我的資料

| 項目 | 內容 |
|---|---|
| 網址與方法 | 一個固定網址，只收 GET，不需再輸入密碼 |
| 誰可以使用 | 未登入：導到登入頁，登入後回來　　已登入：可以（還沒同意目前版本說明的人也可以）　　能否存取他人資料：不能（網址沒有編號） |
| 回傳／顯示的欄位 | **帳號**：使用者名稱、email、出生年、註冊時間<br>**同意紀錄**：每一次的版本、同意時間<br>**問卷**（新到舊）：問卷名稱、作答時間、有沒有戴助聽器（有戴／沒戴／未記錄）、每題（題號、題目文字、分數、選項文字）、總分、分項分數（有的問卷才有）、分級名稱、IOI-HA 的常模組別<br>**聽力圖**（新到舊）：檢查日期、建立時間、每個點（耳別、氣導／骨導、頻率、dB、沒反應、有遮蔽） |
| **不能**回傳／顯示的欄位 | 密碼雜湊、`is_staff`／`is_superuser`、最後登入時間、內部編號（資料庫 id）、`idempotency_key`、行動建議文字、別人的任何資料 |
| 需要計算的資料 | 由誰計算：後端　　計算路徑：`Submission` 的計分方法、`classify()` |
| 空資料時的行為 | 照樣下載；問卷、聽力圖是空清單，不是錯誤 |

- 欄位名稱用英文，內容用中文標籤（例：`"wearing_hearing_aid": "有戴"`、`"ear": "右耳"`）。（2026-10-17 確認）
- 「不適用」寫 `null`，不寫 0：IOI-HA 沒有總分、分項、分級（和網站一致）；HHIE-S／HHIA-S 沒有常模組別。（2026-10-17 確認）
- 同意紀錄由舊到新（看得出同意的歷程）。
- 時間一律用台灣時間（UTC+8），ISO 8601 格式（例：`2026-10-17T14:05:00+08:00`）。
- 格式：JSON，UTF-8，中文直接寫出（不轉成 `\uXXXX`）。
- 檔名：`hearwell-我的資料-2026-10-17.json`（日期是下載當天，台灣時間）。
- 回應不能被瀏覽器或中間代理快取（健康資料）。

- [x] 15. 假設 使用者有一筆 IOI-HA 和一筆 HHIE-S，當 下載，則 IOI-HA 的總分、分項、分級是 `null`，有常模組別；HHIE-S 的常模組別是 `null`。
- [x] 16. 假設 資料庫裡有一題的分數不在該問卷的選項裡（例：HHIE-S 1 分），當 下載，則 仍然下載成功，那一題的分數照實寫出、選項文字是 `null`。（審查 A 追加，2026-10-17 確認）
