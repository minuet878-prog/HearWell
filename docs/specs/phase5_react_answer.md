## 1. 目標

讓 65 歲以上的使用者作答 HHIE-S／HHIA-S 時更不容易出錯：一次只要專心看一件事、每個選項都好按、漏答和送出失敗都有清楚的提示，而且**連按兩次或網路不穩都不會存成兩筆**（用 Phase 5 第 1 項的收據編號）。送出後看到的結果和現在的網頁版一樣。

## 2. 範圍

### 要做
- HHIE-S、HHIA-S 的作答畫面改成 React：一題一頁，選完按「下一題」（助聽器題是第一頁）。
- 「這次有沒有戴助聽器」照現在一樣必填。
- 透過 `POST /api/submissions/` 送出，帶收據編號；網路失敗可以重送，不會重複存。
- 送出成功後，到現有的結果頁。
- 瀏覽器「上一頁」＝回上一題（答案保留）；鍵盤操作、螢幕閱讀器、200% 字級都要能用。
- 作答到一半先儲存（D2）：存在這台裝置的瀏覽器，見 4.2。

### 不做
- IOI-HA 的作答頁（API 不收 IOI-HA，維持網頁版）。
- 修改結果頁、我的紀錄頁、選問卷頁的外觀或行為。
- 修改寫入 API 或計分、分級邏輯。
- 修改登入／註冊。
- 新增作答以外的 React 頁面、前端路由套件、狀態管理套件、UI 元件庫。
- service worker、離線作答。
- 把沒答完的答案存到伺服器、換裝置接著答（另開任務）。
- 網頁版的連按兩次（F-10）：網頁版保留作為 JS 失敗時的備用，這次不處理。
- 修改網頁版 Django 表單本身的行為。

## 3. 必須遵守的規則

- 一律遵守 CLAUDE.md「不可違反的規則」。
- 本任務特別注意：
  - **前端不算分**（第 10 條）：分數與分級只看後端回傳，作答頁不加總、不顯示分數。
  - **字級用 `rem`**（第 13 條）；觸控目標夠大（至少 2.75rem 高，約 44px 以上）。
  - **`main` 隨時完整可用**：JS 載入失敗時，使用者仍然能用原本的 Django 表單作答。
  - **首屏 JS 體積**：作答頁不載入圖表套件，壓縮後（brotli）不超過 80 KB。
  - **測試用假資料**，不放真實作答。

## 4. 行為描述

### 4.1 作答頁

| 項目 | 內容 |
|---|---|
| 網址 | 跟現在一樣 `/questionnaire/<id>`。頁面先由 Django 畫出原本的表單，JS 載入成功後換成 React 版 |
| 誰可以使用 | 未登入：跟現在一樣轉去登入頁，登入後回來　　已登入：可以　　能否存取他人資料：不適用（只送出自己的） |
| 顯示 | 問卷名稱、題數與大約時間、說明文字（沿用網頁版）、助聽器題、每一題與「常常／有時／從未」、進度（第 n 題／共 N 題） |
| **不能**顯示 | 分數、分項、題目分類 |
| 需要計算的資料 | 由誰計算：後端　　計算路徑：`POST /api/submissions/` 回傳的 `Submission` 計分結果 |
| 每一頁 | 一題（或助聽器題）、進度、選項；「上一題」（第一頁沒有）、「下一題」（沒選不能按；最後一題變「送出」）。換頁後焦點移到題目 |
| 上一頁（瀏覽器／手機返回鍵） | 回到上一題，答案保留；在第一頁按才離開作答頁 |
| 漏答 | 沒選不能按「下一題」，正常操作不會漏答；送出前仍再檢查一次，有漏答就提示「還有 n 題沒有回答」並移到第一個漏答的題目，不送出 |
| 送出中 | 按鈕停用並顯示「送出中…」 |
| 網路失敗、伺服器錯誤 | 顯示「送出失敗，請再按一次送出」，答案保留，重送沿用同一個收據編號 |
| 未登入（session 過期） | 送出時 API 回「未登入」→ 顯示「登入已經過期，請重新登入」和登入按鈕，登入後回到作答頁 |
| 送出成功 | 到現有的結果頁 `/submission/<id>` |
| 收據編號用過、內容不同（409） | 顯示「這份作答之前已經送出過」和「到我的紀錄看結果」按鈕，清掉保留的答案（2026-10-16 實作計畫時補充，本人確認 A1） |

### 4.2 作答到一半先儲存（D2）

| 項目 | 內容 |
|---|---|
| 存在哪 | 這台裝置的瀏覽器（不存伺服器、不改資料模型） |
| 存什麼 | 帳號、問卷、助聽器題與每題的答案、答到第幾題、收據編號、存的時間。**不存**分數 |
| 什麼時候存 | 每選一個答案就存 |
| 回到作答頁時 | 有同一個帳號、同一份問卷、7 天內的紀錄 → 先問「您上次答到第 n 題，要接著答嗎？」，按鈕「接著答」「重新開始」。「接著答」回到那一題、答案都在；「重新開始」清掉答案、換新的收據編號 |
| 收據編號一起保留 | 「送出成功但回應沒收到」之後重新整理再送，仍是同一個收據編號，不會存成兩筆 |
| 什麼時候清掉 | 送出成功；按「重新開始」；登出；超過 7 天（打開作答頁時發現就刪）；另一個帳號打開作答頁時，刪掉不屬於自己的紀錄 |
| 存不了的時候 | 瀏覽器不允許儲存（例如無痕模式）→ 照常作答，只是不會保留，不顯示錯誤 |
| 紀錄對不上 | 紀錄裡的題目不屬於這份問卷，或資料壞掉 → 當作沒有紀錄，直接刪掉 |
| 登入過期 | 重新登入回到作答頁時，照上面「回到作答頁時」處理（答案還在） |

## 5. 驗收條件

### 作答與送出

- [x] 假設已登入，當打開 HHIE-S 作答頁，則第一頁是助聽器題，接著每頁一題，共 10 題，題目全文與「常常／有時／從未」都和網頁版一樣。
- [x] 假設在某一頁還沒選答案，則「下一題」不能按；選了之後可以按，並到下一題、焦點在題目上。
- [x] 假設在第 3 題按「上一題」（或瀏覽器上一頁），則回到第 2 題，第 2 題原本選的答案還在；在第一頁按瀏覽器上一頁，則離開作答頁。
- [x] 假設已登入、全部答完，當在最後一題按「送出」，則資料庫多一筆屬於自己的作答，並到這筆的結果頁，分數和用網頁版作答相同答案時一樣。
- [x] 假設每題都選「從未」，當送出，則結果頁顯示總分 0、最輕的那一級。
- [x] 假設答案裡還有漏答（例如保留的答案被改壞），當按送出，則不送出，提示還有幾題沒答，並移到第一個漏答的題目。
- [x] 假設按下送出後、回應回來前又按一次，則只送出一次、只存一筆，按鈕顯示「送出中…」。
- [x] 假設第一次送出時網路失敗，則顯示「送出失敗，請再按一次送出」、答案還在；再按送出時帶同一個收據編號，最後只存一筆。
- [x] 假設伺服器回 400 或 500，則畫面顯示中文錯誤訊息，答案沒有被清掉。
- [x] 假設送出時 API 回未登入，則顯示「登入已經過期，請重新登入」和登入按鈕；登入後回到作答頁。
- [x] 假設作答頁畫面上，則不顯示任何分數或分項。
- [x] 假設送出時 API 回 409（收據編號用過、內容不同），則顯示「這份作答之前已經送出過」和到我的紀錄的按鈕，保留的答案被清掉，不自動重送。

### 作答到一半先儲存

- [x] 假設答到第 4 題時重新整理，則先問「您上次答到第 4 題，要接著答嗎？」；按「接著答」回到第 4 題，前 3 題和助聽器題的答案都在。
- [x] 假設有保留的答案，當按「重新開始」，則回到第一頁、沒有任何答案，之後送出用的是新的收據編號。
- [x] 假設送出成功，當再打開同一份問卷，則不會問「要接著答嗎？」。
- [x] 假設送出成功但回應沒收到，當重新整理、接著答、再送出，則仍是同一個收據編號，資料庫只有一筆。
- [x] 假設保留的答案已經超過 7 天，當打開作答頁，則不問、直接從頭開始，舊紀錄被刪掉。
- [x] 假設帳號 A 答到一半，當帳號 B 在同一台裝置打開作答頁，則 B 看不到 A 的答案，A 的紀錄被刪掉。
- [x] 假設答到一半，當登出，則保留的答案被刪掉。
- [x] 假設 HHIE-S 和 HHIA-S 各答一半，則各自保留、互不影響。
- [x] 假設瀏覽器不允許儲存，則照常作答與送出，不顯示錯誤。
- [x] 假設保留的資料壞掉或題目不屬於這份問卷，則當作沒有紀錄、從頭開始，頁面不壞。

### 並存、體積、無障礙

- [x] 假設 JS 沒有載入，當打開作答頁，則仍是原本的 Django 表單，可以照常作答送出。
- [x] 假設是 IOI-HA，當打開作答頁，則仍是現在的網頁版，不載入 React 作答頁。
- [x] 假設作答頁載入完成，則載入的 JS 不含圖表套件，壓縮後（brotli）不超過 80 KB。
- [x] 假設只用鍵盤，則能選每一題的答案、換頁、送出，焦點位置一直看得到。
- [x] 假設用螢幕閱讀器，則每一頁會唸出「第 n 題／共 N 題」和題目，選項唸得出是單選、哪個被選了。
- [x] 假設瀏覽器字級放大到 200%、畫面寬 320px，則不需要左右捲動，選項不重疊（人工驗收）。
- [x] 假設用 axe 檢查作答頁，則沒有嚴重（serious／critical）問題（人工驗收）。
- [ ] 假設在手機上用返回鍵，則行為和瀏覽器上一頁一樣（人工驗收）。
- [x] 假設答到第 3 題時重新整理、按「接著答」，則按上一頁 4 下回到選問卷頁（第 2、1 題、助聽器題、選問卷頁）；Chrome 與 Safari 各驗一次（人工驗收，2026-10-16 審查 F1 補充）。
