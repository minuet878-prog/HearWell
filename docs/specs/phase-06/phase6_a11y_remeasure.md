## 1. 目標

Phase 2 量過一次、Phase 4 介面改版後只做了人工驗收；Phase 5 又加了 React 作答頁、聽力圖、IOI-HA。照 `docs/accessibility/accessibility_baseline.md` 的同一套方法把全站重新量一次，知道現在還剩哪些問題，再決定修哪些。

背景：roadmap 這一項底下列的 Phase 2 問題（主色對比、導覽列、浮動標籤、`<title>`、觸控尺寸、作答錯誤、選取外框），報告第 3 節記載已在 2026-10-15 介面改版第 1 批處理、本人人工驗收過；這次要用 axe 和手動清單**實際確認**，不是只看紀錄。

### 4.3 修正的行為

**修正一：聽力圖比較頁，320 px**

| 項目 | 內容 |
|---|---|
| 現在 | 數字對照表（項目／舊日期／新日期／差值）撐到約 359 px，整頁變寬，表格上方說明被切掉 |
| 改成 | 整頁不左右捲動；四欄（含「差值」）都看得到：窄螢幕時欄名的日期折成兩行（「2026/」換行「10/16」）；以 320 px 實際畫面確認塞得下，塞不下回來問 |
| 不變 | 表格的欄位、數字、說明文字；桌機畫面 |

**修正二：作答頁（網頁表單）錯誤摘要**

| 項目 | 內容 |
|---|---|
| 適用 | 驗證沒過、重新顯示的網頁表單（6-5 的情況；React 作答頁不動） |
| 摘要何時出現 | 任何一題沒答（含只漏助聽器題）就出現在頁首 |
| 摘要內容 | 第一句維持「還有 N 題沒有回答，請看標示紅字的題目。」（N 含助聽器題；既有測試寫死這句），下面列出每一題的連結（「第 2 題」「第 5 題」…；助聽器題寫成「是否戴助聽器」，排在最前面），按了跳到那一題（整題，題目文字會在畫面內；再按 Tab 到第一個選項）。每個連結是一整塊、觸控至少 44 px（本人 2026-10-16 同意：只把數字做成連結太小） |
| 焦點 | 頁面載入後焦點在摘要上（鍵盤使用者按 Tab 會從摘要往下走） |
| 讀屏 | 進頁面時會唸出摘要內容 |
| 不變 | 每題底下的紅字與它跟題目的關聯；已選答案、收據編號保留（6-5、6-4 的行為）；送出資料格式 |

**修正三：登入失敗訊息**

| 項目 | 內容 |
|---|---|
| 現在 | 紅字「使用者名稱或密碼錯誤」在表單上方，焦點移到密碼欄，但讀屏停在密碼欄時不會唸 |
| 改成 | 使用者名稱、密碼兩欄都標成「有錯誤」，而且讀屏停在任一欄時會唸出「使用者名稱或密碼錯誤」 |
| 不變 | 訊息文字、位置、顏色；名稱留在欄位、焦點移到密碼欄（6-7 的行為）；登入成功的流程 |
