## 1. 目標

讓已配戴助聽器的使用者填 IOI-HA，看到自己每一項助聽器效益跟一般助聽器使用者（常模）相比的位置。常模組別不問使用者，由他「沒戴助聽器」時填的 HHIE-S 分數決定。資料不夠時，寧可說「無法比較」，也不硬給結果。

## 2. 範圍

### 要做
- 新增 IOI-HA **七題版**（中譯，林克寰《助聽器選配與驗證》書頁 167），每題五個選項，計 1–5 分。
- 分組（取代原量表第 8 題）：取使用者**最近一次標記「沒戴」的 HHIE-S** 總分，0–24 → 「輕度至中度」常模，26–40 → 「中重度以上」常模。
- 找不到「沒戴」的 HHIE-S 時照樣可以填，記為「未分組」：結果只列作答、不比常模，並說明需要一筆沒戴助聽器時的 HHIE-S 才能比較。
- 分組在**送出 IOI-HA 時固定**，之後再做 HHIE-S 不會改變舊的 IOI-HA 結果（包括「未分組」也不會事後補分組）。
- 結果頁逐題顯示作答，以及跟該組常模範圍的比較（低於／在範圍內／高於）；**不下總結論**，只加一句固定說明。
- 歷史頁列出 IOI-HA 紀錄：日期、量表名稱、常模組別（或「未分組」）。
- 作答頁說明：本量表適合已配戴助聽器的人（任何登入者都能填，不擋）。
- 作答頁與結果頁底部標示來源：原量表 IOI-HA（Cox 等人）、中譯林克寰、CC BY 3.0 台灣。
- 需要有進入 IOI-HA 的入口；入口的位置與樣子由介面改版第 2 批的首頁動線決定。

### 不做
- 第 8 題（自覺聽力困難程度單一提問），也不當作找不到 HHIE-S 時的備案。
- IOI-HA 作答頁問「這次有沒有戴助聽器」。
- 余思儀助聽器效益量表、CHILD、IT-MAIS、LittlEARS。
- HHIA-S（題目與門檻）；65 歲以下者也只用 HHIE-S 分組。
- 配戴前後 HHIE-S 差值（配戴前 − 配戴後）。
- 問卷適用條件機制（A1 年齡導引、依是否配戴擋人）。
- IOI-HA 的總分、總分切點、「有效益／無效益」之類的總結論。
- 修改 HHIE-S 的題目、門檻、分級文字。
- 用中國版常模。
- 趨勢圖畫 IOI-HA。
- IOI-HA 的 API。既有的歷史與單筆結果 API 只回傳 HHIE-S 紀錄（因此 API 的歷史紀錄不包含 IOI-HA，是已知的限制）。

## 3. 必須遵守的規則

- 一律遵守 CLAUDE.md「不可違反的規則」。
- 本任務特別注意：
  - 分組與常模比較只用規則式程式碼（第 9 條）；分組讀 HHIE-S 分數時，走 `Submission` 的計分方法，不另寫加總（第 10 條）。
  - 找 HHIE-S 紀錄時只能找 `request.user` 自己的（第 8 條）。
  - 「未分組」不能用 0 分或任一組別表示（第 11 條）；HHIE-S 0 分是合法的「輕度至中度」組。
  - 「未記錄」配戴狀態的 HHIE-S 不算「沒戴」。
  - 常模數字由本人核對後才寫進程式；固定分組後，日後改常模不能回溯改寫舊結果（同門檻版本號的原則）。
  - 新文字字級用 `rem`，對比達 WCAG AA。

## 4. 行為描述

### 4.1 IOI-HA 作答頁

| 項目 | 內容 |
|---|---|
| 網址與方法 | 作答頁，GET 顯示、POST 送出 |
| 誰可以使用 | 未登入：導向登入　　已登入：可以　　能否存取他人資料：不適用 |
| 回傳／顯示的欄位 | 說明「本量表適合已配戴助聽器的人」；7 題，每題 5 個選項，不預選；底部來源標示 |
| **不能**回傳／顯示的欄位 | 第 8 題、「這次有沒有戴助聽器」 |
| 需要計算的資料 | 送出時決定常模組或「未分組」（後端） |
| 空資料時的行為 | 有題目沒答 → 不存，顯示錯誤，已選的答案保留；沒有「沒戴」的 HHIE-S → 照樣存，記為「未分組」 |

### 4.2 IOI-HA 結果頁

| 項目 | 內容 |
|---|---|
| 網址與方法 | 結果頁，GET |
| 誰可以使用 | 未登入：導向登入　　已登入：只能看自己的　　能否存取他人資料：不行，回 404 |
| 回傳／顯示的欄位 | 常模組別、分組依據（哪一天的 HHIE-S、幾分）、7 題各自的作答與「低於常模／在範圍內／高於常模」；固定說明「如有多項低於常模，可以帶這份結果跟您的聽力師討論」；底部來源標示 |
| **不能**回傳／顯示的欄位 | IOI-HA 總分、總結論、HHIE-S 的分級文字與建議、「助聽器：未記錄」 |
| 需要計算的資料 | 由誰計算：後端　　計算路徑：常模比較只有一份規則；HHIE-S 分數沿用 `Submission` 的計分方法 |
| 空資料時的行為 | 未分組 → 只列 7 題作答，不顯示比較結果，說明「需要一筆沒戴助聽器時填的 HHIE-S，才能跟常模比較」 |

### 4.3 歷史頁（既有頁面）

| 項目 | 內容 |
|---|---|
| 網址與方法 | 既有歷史頁，GET |
| 誰可以使用 | 未登入：導向登入　　已登入：只列自己的　　能否存取他人資料：不行 |
| 回傳／顯示的欄位 | IOI-HA 紀錄：日期、量表名稱、常模組別或「未分組」、查看結果的連結；HHIE-S 紀錄維持原樣 |
| **不能**回傳／顯示的欄位 | IOI-HA 的總分、分級、「助聽器：未記錄」 |
| 需要計算的資料 | 無（分組已在送出時固定） |
| 空資料時的行為 | 維持原樣 |

### 4.4 趨勢圖與 API（既有）

| 項目 | 內容 |
|---|---|
| 行為 | 只包含 HHIE-S 紀錄；使用者有 IOI-HA 紀錄時，趨勢圖與 API 的回傳跟沒有時一樣 |

## 5. 驗收條件

**作答**
- [ ] 1. 假設已登入，當開啟 IOI-HA 作答頁，則看到 7 題、每題 5 個選項都沒有預選，沒有第 8 題，也沒有「有沒有戴助聽器」題，並有「適合已配戴助聽器的人」說明與來源標示。
- [ ] 2. 假設 7 題中有 1 題沒答，當送出，則不存任何紀錄，畫面顯示錯誤，已選的答案保留。
- [ ] 3. 假設竄改送出的答案為 0 或 6，當送出，則不存，顯示錯誤（不是 500）。
- [ ] 4. 假設未登入，當開啟作答頁，則導向登入頁。

**分組**
- [ ] 5. 假設使用者最近一次「沒戴」的 HHIE-S 是 24 分，當送出 IOI-HA，則固定為「輕度至中度」組。
- [ ] 6. 假設最近一次「沒戴」的 HHIE-S 是 26 分，當送出 IOI-HA，則固定為「中重度以上」組。
- [ ] 7. 假設最近一次「沒戴」的 HHIE-S 是 0 分，當送出 IOI-HA，則為「輕度至中度」組（0 分不當作沒資料）。
- [ ] 8. 假設使用者有一筆較舊的「沒戴」HHIE-S（30 分）和一筆較新的「有戴」HHIE-S（10 分），當送出 IOI-HA，則用 30 分，分到「中重度以上」組。
- [ ] 9. 假設使用者只有「未記錄」或「有戴」的 HHIE-S，或完全沒有 HHIE-S，當送出 IOI-HA，則照樣存下，記為「未分組」。
- [ ] 10. 假設使用者 B 有「沒戴」的 HHIE-S、使用者 A 沒有，當 A 送出 IOI-HA，則 A 為「未分組」，不會用到 B 的紀錄。
- [ ] 11. 假設已送出一筆「輕度至中度」組的 IOI-HA，當之後再做一次「沒戴」的 HHIE-S 得 30 分，則舊的 IOI-HA 結果仍是「輕度至中度」組。
- [ ] 12. 假設已送出一筆「未分組」的 IOI-HA，當之後做了「沒戴」的 HHIE-S，則舊的 IOI-HA 仍是「未分組」。

**結果**
- [ ] 13. 假設某題作答低於該組常模下限，當看結果頁，則該題標示「低於常模」；在範圍內標示「在範圍內」；高於上限標示「高於常模」（兩組各自都測到這三種情況）。
- [ ] 14. 假設已分組的結果頁，當顯示，則看得到常模組別、分組依據（HHIE-S 的日期與分數）、固定說明與來源標示；看不到 IOI-HA 總分、總結論、「助聽器：未記錄」。
- [ ] 15. 假設「未分組」的結果頁，當顯示，則列出 7 題作答，沒有任何「低於／在範圍內／高於」標示，並顯示「需要一筆沒戴助聽器時填的 HHIE-S，才能跟常模比較」。
- [ ] 16. 假設使用者 A 開啟使用者 B 的 IOI-HA 結果，則回 404。

**歷史頁、趨勢圖、API**
- [ ] 17. 假設使用者有一筆 IOI-HA（已分組）和一筆 IOI-HA（未分組），當開啟歷史頁，則兩筆各顯示日期、量表名稱、常模組別／「未分組」，不顯示總分、分級、「助聽器：未記錄」。
- [ ] 18. 假設使用者有 HHIE-S 和 IOI-HA 紀錄，當呼叫歷史紀錄 API，則只回傳 HHIE-S 紀錄。
- [ ] 19. 假設使用者請求自己某筆 IOI-HA 的單筆結果 API，則回 404。

**不影響既有功能**
- [ ] 20. 假設已有 HHIE-S 紀錄，當新增 IOI-HA 功能後，則 HHIE-S 的作答、分數、分級、建議文字、歷史頁顯示都不變。
