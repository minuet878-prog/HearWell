## 1. 目標

使用者可以把自己的篩檢結果整理成一頁「HearWell 聽力報告」，印出來或存成 PDF 帶去給聽力師、醫師看，
讓看診時能快速了解他的自評聽力困擾、變化和助聽器效益。資料匯出（Phase 7）是給程式讀的完整檔案；這份是給人看的摘要。

## 2. 範圍

### 要做
- 一頁**列印友善的網頁**：螢幕上看得清楚，按「列印」可以印出或另存 PDF；內容見 4.1；黑白印也看得清楚。
- 入口：「我的紀錄」頁，「下載我的資料」上方一個顯眼的「聽力報告」按鈕，旁邊一行說明「可以印出來或存成 PDF，帶去給醫師看」。（按鈕名稱 2026-10-17 確認）
- 報告上寫明產生日期、「自我篩檢結果，不是醫療診斷」。

### 不做
- 分享連結、給別人看的網址、家屬帳號（那是 C1，之後再做）。
- 寄 email、上傳到醫院系統。
- 在報告上加任何新的判讀或建議（只呈現網站上已有的分級、聽力圖判讀）。
- 修改計分、門檻、聽力圖判讀；新增要使用者填的資料（例如真實姓名）。
- 選擇日期區間、勾選要放哪幾筆（固定：歷次表列最近 5 次）。
- 伺服器產生 PDF 檔、加 PDF 或字型套件。
- HHIE-S／HHIA-S 每一題的作答。
- 結果頁上的入口。
- 新的 API endpoint；整頁 React 化（只有聽力圖沿用網站現有的畫圖程式）。

## 3. 必須遵守的規則

- 一律遵守 CLAUDE.md「不可違反的規則」。
- 本 phase 特別注意：
  - 只顯示 `request.user` 的資料（規則 8）；網址不帶使用者編號。
  - 分數、分級走 `Submission` 的計分方法，聽力圖走 `interpretation()`（規則 10），不另算。
  - 0 分照實顯示（規則 11）；IOI-HA 沒有總分與分級（和網站一致）。
  - 字級用 `rem`（規則 13）；印成紙也要讓 65 歲以上的人看得清楚。
  - 這是健康資料頁面：需要登入、需要同意（不開同意閘門的例外）。

## 4. 行為描述

### 4.1 HearWell 聽力報告

| 項目 | 內容 |
|---|---|
| 網址與方法 | 一個固定網址，GET |
| 誰可以使用 | 未登入：導到登入頁，登入後回來　　已登入但未同意：導到同意頁　　能否看到他人資料：不能 |
| 顯示的內容 | ① 開頭：使用者名稱、出生年與年齡、產生日期、一條空白「姓名：＿＿＿」供手寫<br>② HHIE-S／HHIA-S（各自一段，有紀錄才出現）：最近一次的日期、總分、分級、情緒／社交分項、助聽器（有戴／沒戴／未記錄）；歷次表（日期、總分、分級、助聽器），最近 5 次，寫「共 N 次，列出最近 5 次」<br>③ 戴助聽器前後的分數差（網站「我的紀錄」已有的計算，有資料才出現）<br>④ IOI-HA（有紀錄才出現）：最近一次的日期、常模組別、每題的選項文字與常模比較（和結果頁一致）<br>⑤ 聽力圖（有紀錄才出現）：最近一張的檢查日期、**畫成聽力圖**（和網站一樣）、左右耳四頻平均、程度、類型 |
| **不能**顯示的內容 | 使用者名稱以外的帳號資料（email）、密碼、內部編號、別人的資料 |
| 需要計算的資料 | 由誰計算：後端　　計算路徑：`Submission` 計分方法、`classify()`、`Audiogram.interpretation()` |
| 版面（2026-10-17 本人從比較頁選 C） | 標題「HearWell 聽力報告」→ 開頭 ① → **重點摘要框**（每行一項，有資料才出現：聽力圖左右耳四頻平均與程度、類型；HHIE-S／HHIA-S 最近一次總分與分級、助聽器；配戴前後分數差；IOI-HA「7 項中 N 項低於常模、M 項高於常模」）→ 細節依序：⑤ 聽力圖 → ② HHIE-S／HHIA-S → ③ 配戴前後 → ④ IOI-HA → 免責聲明。可以超過一張紙 |
| 空資料時的行為 | 還沒有任何問卷和聽力圖：顯示「還沒有可以放進報告的紀錄」和「開始篩檢」連結，不顯示列印按鈕 |

- [x] 3. 假設 未登入，當 打開報告網址，則 被導到登入頁，登入後回到報告。

- [x] 5. 假設 沒有任何紀錄，當 打開報告，則 看到「還沒有可以放進報告的紀錄」和開始篩檢的連結，沒有列印按鈕。
- [x] 6. 假設 某次 HHIE-S 總分 0，當 打開報告，則 顯示 0 分和對應分級（不是空白）。
- [x] 7. 假設 任何報告，則 寫明產生日期（台灣時間）和「自我篩檢結果，不是醫療診斷」。
- [x] 8. 假設 列印報告，則 網站的導覽列、頁尾、按鈕都不會印出來，內容黑白也分得清楚（不只靠顏色區分分級）。
- [x] 9. 假設 使用者有 20 筆問卷，當 打開報告，則 資料庫查詢次數固定（不能有 N+1）。
- [x] 10. 假設 已登入，當 看「我的紀錄」頁，則 有「聽力報告」按鈕連到報告，旁邊有「可以印出來或存成 PDF，帶去給醫師看」。

- [x] 12. 假設 A 只有 HHIE-S、沒有 IOI-HA 和聽力圖，當 打開報告，則 只出現 HHIE-S 那一段，沒有空的 IOI-HA、聽力圖段落。
- [x] 13. 假設 A 有 2 張聽力圖，當 打開報告，則 畫的是最近一張（檢查日期最新），圖上左右耳的點和那張聽力圖一致；瀏覽器沒有 JavaScript 時，仍看得到判讀文字。
- [x] 14. 假設 A 同時有戴與沒戴助聽器的 HHIE-S，當 打開報告，則 顯示前後分數差，數字和「我的紀錄」頁一致。
- [x] 15. 假設 A 有聽力圖、HHIE-S、IOI-HA，當 打開報告，則 最上面有重點摘要框，每一行的數字和下方細節一致；IOI-HA 那行的低於／高於常模項數和下方表格的比較結果相符。
- [x] 16. 假設 任何報告，則 頁面標題與報告標題是「HearWell 聽力報告」；細節段落的順序是聽力圖 → 問卷 → 配戴前後 → IOI-HA。
