## 構想（還沒排進任何階段）

工作量：小／中／大。

### 問卷
- **COSI**：第三批只做了 THI（見已完成），COSI 先不排；要做時先解決自行填答與原施測流程的差異，訪談與來源見 [questionnaire-comparison.md](planning/adult-assessment/questionnaire-comparison.md)。

### 追蹤與紀錄
- **情境日記**（中）：記錄在哪些情境聽不清楚。
- **定期重測提醒**（中）：email 或 PWA 推播；推播需要 service worker，要一起重新評估。
- **聽力圖**：四頻平均的趨勢圖、三張以上比較。
- **伺服器端中途儲存**（換裝置接著答）。

### 衛教與資源
- **C2 衛教內容**、**助聽器相關內容**（小～中）。
- **助聽器補助流程指引**：內容型功能，補助規定會變，要標明資料時效。
- **就醫地圖**（中）：健保特約醫事機構開放資料，定期抓回、重抓要冪等。有耳鼻喉科不代表有聽力師，文案不能寫成「可做聽力檢查的地方」。
- **身障鑑定醫院、輔具中心查詢**（中）：各縣市格式不一，輔具中心可手動整理成 fixture。
- **問答小助手**：先做 FAQ＋關鍵字比對（零成本、答案都經本人審核，不呼叫 AI API）；之後可升級 RAG 版（大），知識庫只用審核過的內容、附來源、超出範圍拒答、要有 eval，LLM 不做分級或計分。

### 聽力檢測
- **聽力圖照片辨識 → 判讀 → 衛教**（大）：先只做北榮固定格式，手動輸入當備援。
- **數字噪音測驗**（digits-in-noise）（大）：有文獻驗證，對耳機校正要求比純音低。
- **純音自我篩檢**（大）：無法校正、可能涉及醫療器材法規，先查法規。
- **環境噪音分貝計**（中）：麥克風未校正，只能當參考值。
- **聽損／助聽器模擬**（大）：讓家屬體驗聽損者聽到的聲音。

### 家屬與臨床端
- **臨床端檢視**（大）：病人同意後聽力師可看紀錄，難點是權限與同意。
- **台語語音轉寫給臨床人員**（大）：例如 Breeze-ASR-26。
- **家屬頁加內容**：「看懂篩檢結果」「照顧者也要照顧自己」。
- **分享連結**：多個連結、記錄給誰、自訂期限。

### 無障礙與語言
- **台語語音問卷**（大）：唸題目、語音作答；要處理耳機、語速、大按鈕。
- **題目朗讀**（TTS）（小～中）：先做國語版。
- **字級切換按鈕**（小）。

### 工程面
- **前端錯誤監控**：要先評估 JS 體積。
- **e2e 加動線**：聽力圖、JS 關閉時的表單（IOI-HA 網頁表單改走 React 後，真瀏覽器裡沒有測試送它）、WebKit／桌機大小。
- **分數快取或改存欄位**（中）：要先想清楚何時失效（`_scores_cache` 已經有不會失效的坑）。
- **匿名統計後台**（中）：看整體分數分布。
- **上架原生 app**（大）：DRF 加 token 驗證，endpoint 不必重寫。
