# 0006 動態效果：只播一次、可以關、只給能點的東西

日期：2026-10-21（本人審定，設計系統第 2 階段拷問 Q2、Q5；規格 #120）

## 情境

設計系統第 2 階段要讓網站「更有動態感」（頁首聲波會流動、可點的卡片滑過會浮起）。使用者多是 65 歲以上：容易頭暈的人不少，多數人不知道手機有「減少動態效果」設定，而且主要用手機，手機沒有「滑過」，點完滑過樣式還會卡住。WCAG 2.2.2（A 級）要求自動播放、超過 5 秒、和內容並存的動畫要能暫停。

## 決定

- 自動播放的動畫只播一次，約 4 秒內停住；不做無限循環（除非另外做暫停鈕，這次不做）。
- 頁首聲波在同一個瀏覽器分頁裡只有第一頁會播，之後換頁直接停在最後的樣子；關掉分頁再開算新的一次。沒有 JavaScript 時每頁都播。（2026-10-21 #120 拷問）
- 系統開了「減少動態效果」：完全不動，也不位移，只保留顏色變化。
- 滑過效果（浮起、陰影、漣漪）只給可以點的東西，而且只在有滑鼠的裝置上出現；手機改成按下時下沉、放開恢復。
- 位移（浮起、下沉）只給可點的卡片；按鈕、導覽項目、作答選項的回饋是變色，不位移；鍵盤焦點也不位移，用焦點框標示。（2026-10-21 #120 拷問）
- 不能點的框（不是連結也不是按鈕的框，例如步驟卡、趨勢摘要）滑過和按下都沒反應，免得被當成按鈕。（2026-10-21 #120 拷問：原本寫「步驟卡、分數方塊」，改成通則）
- 不做卡片進場動畫、數字往上跑。
- （2026-10-24）按下也要變色、三種只播一次的位移例外，見 ADR 0028。

## 理由

播一次就停，不用多一顆暫停鈕就符合 2.2.2，長者也不用多學一個控制項。滑過效果給不能點的東西，長者會去點、點了沒反應，比沒有效果更糟。

## 代價

「一直活著」的感覺比較弱，每頁只在進來時動一下。以後每加一個動畫，都要對照這三條檢查。
