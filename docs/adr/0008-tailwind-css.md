# 0008 樣式改用 Tailwind CSS

日期：2026-10-21（本人審定，設計系統第 2 階段拷問 Q13–Q17、Q20；規格 #119）

## 情境

網站樣式是 Bootstrap 5.3（CDN）加一份約 1100 行的自訂 CSS。自訂 CSS 有不少地方在覆寫 Bootstrap 的預設（按鈕要逐一改變數、文字色用 `!important`），設計數值散在各處。第 2 階段改版要加一批新的顏色、圓角、陰影，照現在的寫法只會再疊更多覆寫。兩套框架也不能並存：`p-3`、`mb-3`、`container` 這些 class 名稱相同、數值不同。

## 決定

- 全站改用 Tailwind CSS v4，用專案已有的 Vite 建置（官方 Vite 外掛），掃描 Django 模板和 React 原始碼；Bootstrap CDN 拿掉。
- 分兩步：先遷移、畫面不變（截圖前後比對驗收），再做第 2 階段的新外觀。
- 在一條功能分支上分票做完，一次合併回 `main`；遷移期間會動到模板的其他工作先停。
- 重複出現的元件（按鈕、表單、卡片、表格、提示框）和現有的自訂 class 保留成有名字的 class，用 Tailwind 的設定值定義；用拼接產生的 class（例如依分級加的 class）也走這條。只用一次的排版和間距直接寫 Tailwind。
- `AGENTS.md`、`CODING_STANDARDS.md` 在遷移的最後一張票、跟著合併時才改，讓文件描述的永遠是 `main` 的現況。

## 理由

設計數值集中在一個地方，Django 模板和 React 用同一套；不必再跟框架的預設值打架；只打包用得到的 CSS，也少一個外部 CDN。先遷移再改外觀，出問題時分得清是換框架還是新設計造成的。Tailwind 在業界常見，對本人轉職的作品集也有幫助。

## 代價

整站重寫：約 31 個模板、475 處 Bootstrap class，React 約 63 處，表單自動加的 class，以及約 7 個直接讀 CSS 文字的測試（改成在 e2e 的瀏覽器裡量）。CSS 變成建置產物，平常的測試指令讀不到。新外觀要等遷移完成才看得到，遷移期間其他動到模板的功能要排在後面。
