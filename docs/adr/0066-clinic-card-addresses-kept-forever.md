# 0066 診間小卡用專用網址，永久保留，轉到落點才計數

日期：2026-11-16（本人審定，[「讓家屬找得到」第 6 項拷問決定](../planning/found-by-family/clinic-card-grill-decisions.md) Q5、Q7、Q15）

## 情境

本人要在診間發印有 QR code 的小卡，分長輩卡和家屬卡，也想知道每月有多少人從小卡進來。規劃原本寫在落點網址後面加一個來源參數。

## 決定

- 兩種卡各有一個小卡專用的短網址，QR code 裡放的是它。打開後轉到落點（長輩卡：先問年齡的篩檢頁；家屬卡：家人專區首頁），網址帶一個小卡標記。
- 落點頁真的在瀏覽器裡打開後，由頁面送一個小請求在匿名月計數加一，再把網址上的標記拿掉。跟第 5 項的兩個門、「從傳給他打開」同一種做法。
- 這兩個網址是 `/c/e`（長輩卡）和 `/c/f`（家屬卡）（#680 定），永久保留，以後不改、不拿來做別的用途；要換落點只改轉去哪裡。小卡標記是 `via=clinic-elder`、`via=clinic-family`。
- 短網址帶禁止收錄、不進 sitemap，`robots.txt` 不動（ADR 0062）。

## 理由

印出去的卡收不回來。QR code 直接放落點網址加參數的話，網站改版時落點網址就不能動，還要避開已經被保存卡用掉的 `?from=card`。短網址的 QR code 格子少，印在名片大小上比較好掃。轉頁時就計數的話，LINE 抓預覽、搜尋引擎都會被算進去，而且 User-Agent 不一定認得出它們；由頁面計數再拿掉標記，重新整理或再轉傳也不會重算。

## 代價

多兩個不能刪的網址，以後整理網址時要記得留著它們。關掉 JavaScript 的人不會被算到。計數只是大概的數字：同一個人掃兩次算兩次，有心人亂打也會多算。
