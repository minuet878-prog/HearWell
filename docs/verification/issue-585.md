# 公開頁面清單與預設禁止收錄（#585，規格 #583）

日期：2026-11-16。分支：`feat/585-public-page-list`。

不需交叉審查：不碰計分、分級、門檻、migration、權限（規格 #583「審查」）。做了自審，見下方。

## 做了什麼

- 全站每個回應預設帶禁止收錄的標頭（`X-Robots-Tag: noindex`），在一個 middleware（每個請求都會經過的一層程式）統一加：頁面、導向、錯誤頁、API、管理後台都算（ADR 0062）。
- 新模組「公開頁面清單」：只有清單上的網址、而且回 200，才不帶這個標頭。
  - 固定的 13 頁：首頁、了解、聽損模擬、隱私權說明、家人專區 7 頁、選配指引首頁、問答首頁。
  - 從既有定義展開：選配指引 6 章、有題目的問答主題（現在 3 個）、問答的每一題（現在 7 題，含轉介答案）。
  - 現在一共 29 個公開頁面。新增一題問答、或「網站怎麼用」有了第一題，會自動變成公開頁面，不用另外登記。
- 分享報告、列印報告、監控測試頁、運作檢查原本自己加的 `noindex, nofollow` 沒有被蓋掉。
- `test_standards.py` 加全站掃描：走過每個網址樣式，沒登入用 GET 和 POST 各打一次，不在清單上的都要帶禁止收錄；清單上的都要回 200、不帶。

## 實作時的做法（請本人知道）

- **靜態檔（樣式表、圖片）不帶禁止收錄**。它們不是頁面；之後 LINE 的預覽圖也是靜態檔，不希望它帶著這個標頭。規格沒有寫到靜態檔，這是我定的。
- **`http://` 轉 `https://` 的那一次導向不帶**。正式站這一步由 nginx 做（還沒進到網站程式），本來就不帶；轉過去的目的地會帶。
- **公開與否只看網址，不看登入狀態**（規格的決定）：已登入的人打開首頁，回應一樣不帶禁止收錄。搜尋引擎不會登入，所以收錄到的是沒登入的樣子。
- **帶參數的公開頁面一樣可以收錄**（例如 `/guide?edit=x`）。重複網址的問題留給 #589 的標準網址標記處理。
- **順手改了一處既有程式**：問答主題頁「這個主題列哪幾題」原本寫在頁面裡，抽成一個函式，讓清單用同一份判斷。畫面沒有變。
