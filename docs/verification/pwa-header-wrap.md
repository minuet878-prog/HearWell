# 頁首在手機上把登出擠到第二行（小改動，無 issue）

日期：2026-10-21。基準：`90dec32`（main）；分支：`fix/pwa-header-wrap`；commit：`bca2908`、`b4bfdfc`。

狀態：等本人驗收。自動測試與自審（Standards／Spec）已通過。小改動，沒碰計分、門檻、資料 migration、權限，不需交叉審查。未操作真實資料；沒有啟動開發伺服器，截圖都在 e2e 的臨時測試資料庫上拍。不需 migration。

## 問題與根本原因

加到主畫面的 App 版頁首多了「上一頁」，登出（連同「目前登入：xxx」）被擠到第二行；帳號名稱長的時候，網頁版也會。

390px 手機可用寬度 363px：左邊「上一頁＋HearWell」243px，右邊「目前登入：xxx＋登出」最短也要 211px，加起來放不下，右邊整組換行。原本的 e2e（`test_back_button_fits_a_phone_at_double_text_size`）只檢查「同一行時不重疊」，允許換行，所以沒抓到。

## 行為

- 手機（< 48em）：第一行「上一頁｜HearWell｜登出」，第二行「目前登入：xxx」（點了進帳號設定）。名稱太長就在第二行換行，不影響登出。
- 桌機（≥ 48em）：維持一行；名稱太長時在自己的位置換行，登出固定在最右邊。
- HTML 順序不變（帳號連結在登出前），螢幕閱讀器和 Tab 順序仍是 上一頁 → HearWell → 目前登入 → 登出。手機上畫面順序和 Tab 順序不同（焦點會從第二行的名稱跳回第一行的登出），這是刻意的取捨：名稱在登出前讀出來，意思比較通順。
- 改動：`layout.html` 拿掉包住帳號連結和登出的外層 div；`styles.css` 新增 `.site-header-bar` 的排版規則。未登入時頁首只剩左邊一組，不會多出空行。

## 人工驗收

請在手機上操作：

1. 加到主畫面的 App 版，登入後進「開始篩檢」或「我的紀錄」：上一頁、HearWell、登出在同一行，「目前登入：xxx」在下一行，點了會進帳號設定。
2. 手機瀏覽器（不是 App 版）同樣確認一次。
3. 電腦瀏覽器：頁首一行，名稱在登出左邊。
4. 登出後看首頁：頁首沒有多出空白的第二行。
5. （有藍牙鍵盤或電腦時）按 Tab：順序是 上一頁 → HearWell → 目前登入 → 登出，焦點框都看得到。
