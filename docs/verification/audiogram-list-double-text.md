## 問題與根本原因

#268 驗收時發現（[issue-268.md](issue-268.md)「已知限制」）：手機字放大 200% 時，`/audiograms` 整頁撐到 517px（390px 和 320px 都一樣），要左右捲動。

原因：每張聽力圖卡片（`a.link-card`）裡的縮圖是 `flex: none; width: 6rem`，字放大到 225%（網站基礎 112.5% 的兩倍）時寬 216px，右邊的 `.link-card-body` 被擠到 0 寬，日期和兩耳程度標籤（`.level-badge`）只能超出卡片，撐寬整頁。改版前就有，跟導覽改版無關。

## 做法（本人選定）

- 2026-10-23 本人看比較頁後選 **A：字放大時縮圖移到上方、仍跟字一起放大**（建議案）。比較頁是實際樣式的 Chromium 截圖，畫了現況與 A／B／C／D 四案在 390px 一般字級、390px 200%、320px 200%；D（縮圖大小上限、留在左邊）量過仍撐到 409px。比較頁放在暫存資料夾，不進版控。
- 卡片加上 `audiogram-card`（`audiogram_list.html:20`），比照 `.action-card`：卡片自己當容器，平常不換行；卡片內容寬度小於 13.5rem 時（`site.css:3636`），日期和兩耳程度換到下一整列，縮圖改成撐滿第一列、跟箭頭並排，維持 4:3。
- 門檻 13.5rem 的理由：320px 一般字級時卡片內容約 13.97rem，不會觸發；小於 13.5rem 時，縮圖 6rem＋兩個間距 2rem＋箭頭後，右欄已放不下日期（約 5.1rem）。比 320px 更窄的手機（例如 280px）在一般字級也會換成上下排，那是放不下時才換，原本在那種寬度日期也會擠出右欄。
- 實測（靜態頁、正式建置的樣式）：390px 與 320px 在一般字級和 200% 字級都不左右捲動；320px 200% 時日期右緣 252px、標籤右緣 252px，都在卡片（右緣 293px）裡。
