## 問題與根本原因

在試 e2e 平行執行（`--parallel 4`）時發現：`test_form_9_anchors_jump_to_their_sections` 平行跑 3 次都失敗，
依序跑會過。失敗時打開 `/guide/form-9#reapply`，畫面捲過「再次申請（換新機）」，停在下一節。

用暫時的探測測試（試驗完已刪除）比較各種條件，每種跑兩次：

| 條件 | 結果 |
|---|---|
| 捲動途中字型才到，平滑捲動開著 | 捲過頭 83px |
| 字型一樣晚到，關掉平滑捲動 | 停在標題上 |
| 字型全部擋掉（不換字型），平滑捲動開著 | 停在標題上 |

根本原因：網站對整頁開了 `scroll-behavior: smooth`。從別頁跳進來時，瀏覽器先算好目標位置，開始平滑捲動；
捲到一半某組字型才到，上方文字重新換行（這次是「九號表找誰開」三個縣市的電話號碼從兩行變一行），標題往上移，
平滑捲動卻照原本的終點停下。不是平滑捲動時，瀏覽器會在版面變動後自動把位置對回標題。

依序跑時本機伺服器快，字型在捲動前就到了；平行跑時電腦忙，字型晚到。真實使用者在手機網路慢、第一次開這一頁時
也會遇到；系統開了「減少動態效果」的人不受影響。

## 行為

- 頁面載入完（`load`）而且字型就緒（`document.fonts.ready`）之後，才在 `<html>` 加上 `smooth-scroll`，
  平滑捲動只在有這個 class 時生效（`frontend/src/site.css`、`layout.html` 的 inline script）。
- 從別頁跳進來：直接跳到段落，字型晚到時瀏覽器會自動對回標題。
- 同一頁內的跳轉（家人溝通頁的主題目錄、「跳到主要內容」）：載入後照舊平滑。
- 「減少動態效果」：維持立即跳轉，跟以前一樣。
- 沒開 JavaScript：class 不會加上，平滑捲動一直關著，跳轉都是立即的。以前沒有 JavaScript 也會平滑；
  這是刻意的取捨，不影響能不能用。
- 每頁多一個很短的 inline script，`test_only_expected_scripts` 的各頁清單已一併更新。

### 修正前先失敗（紅燈）

重現測試讓瀏覽器先拿不到字型，等頁面開始捲動才放行，再等捲動停下來檢查。修正前在舊程式上連跑 3 次都失敗；
合併最新 `main`（#250 改了選配指引內容）後，暫時把 CSS 改回舊寫法再跑 3 次也都失敗，改回修正後 3 次都通過。

自審後發現：舊 CSS 在新內容上，標題偏離頂端 56px 但仍在畫面內，原本「在畫面內就算過」的斷言可能漏掉，
所以改成「離頂端 10px 內」；改完後舊 CSS 確實失敗（`55.9 not less than 10`）。
