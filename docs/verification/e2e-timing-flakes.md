# e2e 滑塊與亮框測試的時間問題

日期：2026-11-05；分支 `fix/e2e-timing-flakes`（從 `main` 的 `d9503cc` 開出）。
狀態：只改測試和文件，自動驗證完成；**不需交叉審查**（不碰計分、門檻、資料或權限）。沒有畫面改動，不需要實際操作驗收。

## 起因

本人請我盤點所有 CI 失敗的 commit，其中兩個 e2e 測試程式沒改也會失敗，功能本身正常：

- `test_knob_slides_only_without_reduced_motion`：`b2b31d1` 重跑失敗，動畫清單應有一筆，讀到空的。
- `test_section_box_lights_after_a_jump_from_another_page`：`ebd9d65`、`f823801` 失敗，亮框時間 2787、2799.5 ms，要求大於 2800。

第三個不穩定的 `test_browser_tab_and_no_javascript_show_every_card` 已在 10-23 由 `2d66fd7` 修好（改掉 `networkidle`），這次沒有動。

## 根本原因

**滑塊：** 點擊之後才讀 `getAnimations()`。滑動是 0.2 秒的 CSS transition，跑完就從清單消失，機器慢時讀到的就是空清單。

**亮框：** 測試用「最後一個亮的畫面減第一個亮的畫面」量時間，有兩個誤差：

1. 淡出尾端透明度捨入成 0，正常就少量約 115 ms，只量到約 2885 ms，離 2800 只剩約 85 ms。
2. 瀏覽器在上燈時忙碌多久，第一個畫面就晚多久。

## 修法

**滑塊：** 點擊前掛 `transitionrun` 監聽，動畫一開始就記下屬性和長度。

**亮框（`assert_lights`，6 處呼叫一起修好）：**

- 上燈和熄燈的時刻改由頁面記錄 class 加上、拿掉的時間，門檻 2800、3300 沒變。「亮滿」「淡出」的時間窗也從這個時刻起算。
- 新增兩項檢查，補回只量 class 會少驗的部分：動畫長度要是 3000 ms（減少動態時沒有動畫）；拿掉 class 後畫面上不能再亮。
- 從頁面一開始就監聽 `document`，不等 `DOMContentLoaded`。

自審時標準軸和規格軸抓到第一版的 3 個問題：畫面亮多久沒有上限、下限從 2800 放鬆成 2600、監聽器掛太晚。前兩個都補回來了。第三個在目前的路徑沒有重現，但實測上燈只比 `DOMContentLoaded` 晚 5.6–18 ms，餘裕很窄，所以一起修。

## 驗證

都是試驗，做完已還原。環境是本機 Mac，用 CPU 降速和人工卡頓模擬較慢的 CI。
